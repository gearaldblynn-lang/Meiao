## 二、问题条目

### 问题1(数据类):`.env.server` 管理员引导账号在本地模式下不存在,登录 401

- **板块**:登录 / 账号体系
- **复现步骤**:
  1. 读 `.env.server` 取 `MEIAO_ADMIN_USERNAME`(=admin)与 `MEIAO_ADMIN_PASSWORD`
  2. `curl -X POST http://127.0.0.1:3100/api/auth/login -H 'Content-Type: application/json' -d '{"username":"admin","password":"<env里的密码>"}'`
- **预期 vs 实际**:预期 env 引导的管理员能登录;实际 **HTTP 401 `{"message":"用户名或密码不正确。"}`**。用同一密码试 `将离` 也是 401。
- **实际代码路径**(读码+数据核实,未插探针):
  - 本地模式登录 handler:`server/index.mjs:11069`(注意:`/api/auth/login` 有**双 handler**,MySQL 模式在 `server/index.mjs:9210`,本地模式在 11069 —— 与根因库里"同名路由双 handler"坑同款结构)
  - 本地用户存储:`server/data/internal-store.json` → `users` 数组只有 `将离`(admin)、`测试`(staff)、`测试1`(admin),**没有 `admin` 用户**
  - `MEIAO_ADMIN_USERNAME` 在本地模式下只用于超管名单判定(`getSuperAdminUsernames`,`server/index.mjs:1183-1192`),**不会引导创建本地用户**;`server/index.mjs:14440` 打印的 "Default admin bootstrap user" 与本地 store 实际内容脱节
- **归类**:数据类(env 配置与本地 store 数据不一致;引导逻辑只覆盖 MySQL 模式)
- **影响**:本地模式下按 env 文档登录必失败;自动化脚本/新同事按 `.env.server` 操作会被挡在门外。本次巡检靠复用 store 里 `将离` 的未过期 session token 才继续。

### 二、新增问题条目(接力编号续 B)

### 问题5(调度类·本次最重要):常驻后端进程 HTTP 活着但 temporal worker poller 已死,任务永远 queued;`npm run local` 静默复用它

- **板块**:任务调度(通用,所有 job 类板块都会中招)
- **现象**:翻译任务 201 queued 后 23 分钟不动;temporal `task-queue describe meiao-local` 显示 workflow backlog=2、**Pollers 列表为空**(无人拉取)。
- **根因链**:
  1. 3100 上跑的是**用户 launchd 常驻服务**(`~/Library/LaunchAgents/com.meiao.current.server.plist`,KeepAlive=true;配套 `com.meiao.current.vite` 占 3000)——当时的实例(pid 43260,6/29 拉起)HTTP 正常应答,但 temporal worker poller 已停止拉取,**"API 层活着 + 执行层死了"的半僵尸状态**,而 launchd 只看进程存活,不会替它重启;
  2. `scripts/local-dev.mjs`(`scripts/local-dev.mjs:58-75`)检测到 3100 是 node 进程就打印"将复用现有后端"**静默复用**,不校验其 worker 是否健康,于是巡检者以为自己启动了新服务;
  3. worker 与 HTTP server 同进程启动(`server/index.mjs:14396` `startMeiaoTemporalWorker`),没有独立健康信号;`/api/health` 只报 `{"ok":true}`,不含 worker/poller 状态。
- **复现步骤**:让一个 server 实例占住 3100 且 worker poller 断连 → `npm run local`(输出"3100 已在运行…将复用现有后端")→ POST 任一 `/api/jobs` → 永远 queued;`temporal task-queue describe --task-queue meiao-local` 看 Pollers 为空即实锤。
- **修复验证**:kill 43260 → launchd KeepAlive 自动重生新实例 → 新实例 poller 出现(`53419@iMac.local`),积压 2 个 workflow task 立即被消费,翻译任务转 `succeeded`。即**杀掉重生即恢复,病灶是 poller 断连后进程内无自愈、外部无感知**。
- **归类**:调度类(候选改进:①`/api/health` 附带 worker poller 心跳/最近拉取时间;②local-dev 复用后端前查队列 poller;③worker 断连应进程内重连或主动退出让 launchd/PM2 重拉;④这大概率也是历史"任务卡处理中"类投诉的一种成因,值得对照云上日志)
- **附带证伪**:B 时段买家秀 51 秒完成,说明 B 巡检时该实例 poller 还活着,poller 是其间某时刻死的——不是"从来没有 worker"。
