## 七、修复优先级建议(按影响排序)

1. **上游类占 6 成,单一最大项是 `fetch failed`(87次/7天,跨 5+ 模块,慢性)**——建议优先排查服务器到 KIE/中转站的网络链路与重试策略(是否有超时过短/无重试/DNS 问题),以及中转站自身过载(503 cpu overloaded、Concurrency limit、Internal Error 合计 ≈30 次)。
2. **结果资源抓取 404(32次)**——KIE 出图成功但结果 URL 拉不回来,疑似结果文件过期/鉴权,值得单独修。
3. **调度类:31 次"上次会话未正常关闭" + 21 次取消 + 历史 Heartbeat timeout 231 次**——与"任务卡死/卡处理中"用户体感直接相关。
4. **数据类量小但用户体感差**:素材无公网地址(8)、本地缓存失效(6)——都是"让用户重新上传"的挫败路径。
5. **KIE 余额不足(3+3次)与积分不足(5次)**——运营配额问题,建议加余额预警。
6. 前端 `Failed to fetch dynamically imported module`(2次)——部署新版本后旧页面引用旧 hash 资源,属发布策略问题(保留旧 assets 或强刷提示)。
