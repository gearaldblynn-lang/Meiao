# Logo 替换 AI 原生工作流实施计划

日期：2026-08-02

## 红线

- 保留当前工作区已有的出海翻译改动。
- 不部署、不推送、不提交，除非用户另行要求。
- 活动 Logo 工作流禁止调用本地清理合成或 Canvas Logo 叠加。
- 新提示词按 RTCFE 编写并补回归测试。
- 分析和生图图片输入必须保留顺序及重复 Logo。
- 真实付费验收只创建一次最小任务；拿到任务 ID 后只查询或恢复，不重复创建。

## 实施步骤

1. 为区域数据增加 `replacementRequirement` 归一化和持久化测试。
2. 新增 Logo 分析合同：
   - RTCFE 分析提示词。
   - 严格 JSON 解析。
   - 精确区域覆盖和 Logo 映射校验。
   - 固定生图提示词编译器。
3. 新增编号区域标记图生成器，只画区域和编号，不合成 Logo。
4. 在分析服务增加 `logo_replace_analysis` 多模态控制任务。
5. 重写 Logo 工作流：
   - 统一角标、单 Logo、多 Logo。
   - 原图、标记图、按区域排序的 Logo 进入分析。
   - 分析结果编译为详细提示词。
   - 同一组有序素材直接进入生图。
   - provider 返回的完整结果图进入统一终态处理，不做客户端局部清理、Logo 贴回或区域合成。
6. 在框选弹窗增加每区域替换要求输入，并保存到素材快照。
7. 把 `logo_replace_analysis` 纳入 shell 控制任务可见性合同。
8. provider 成功后校验整图比例，恢复原画布尺寸，转存站内受管资产并回写 generation job。
9. provider 生图与最终资产处理成功后直接完成；不创建出图后 AI 审查、审查证据或额外积分任务。
10. 运行定向测试、lint、build、verify。
11. 启动本地应用，使用一组非敏感电商主图和 Logo 完成一次真实任务。
12. 在真实浏览器中由人检查 Logo 身份、区域映射、旧标残留、融合、标记清除和框外稳定性，并确认页面不会出现后置审查失败。

## 验证边界

- 代码验证：测试、类型检查和构建。
- provider/素材链验证：分析任务、生成任务、输入顺序、最终托管图片。
- 浏览器视觉验收：实际页面结果和截图。
- 本轮不做云上发布，因此不得把本地结论写成生产环境已生效。
