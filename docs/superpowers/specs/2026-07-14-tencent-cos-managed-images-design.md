# 腾讯 COS 托管图片存储设计

- 日期：2026-07-14
- 状态：已确认，待实施计划
- 适用仓库：梅奥 MEIAO 当前版本

## 1. 背景

当前浏览器上传图片后，前端虽然调用名为 `uploadToCos` 的服务，但后端实际把图片写入云服务器本地目录，并通过 `/api/assets/file/:assetId/:name` 提供稳定访问地址。生成服务偶发无法从该地址抓取素材，云服务器重启、负载和公网链路也会直接影响外部模型读取。

项目已经有一条仅供 Gemini 完整视频使用的私有腾讯 COS 链路：服务端上传视频、生成短期签名 GET URL，再交给模型读取。现有视频桶、密钥权限和生命周期仅覆盖 `gemini-video/*`，不能直接扩展为全站图片存储。

本设计把新版本之后所有模块上传的用户原图、参考图和聊天图片改为腾讯 COS 托管，同时保持现有业务地址和历史素材兼容，并保证用户删除后 COS 对象最终被物理清理。

## 2. 目标

1. 新版本之后，所有模块新上传的用户图片统一写入独立的腾讯 COS 私有图片桶。
2. 外部分析和生成模型获得可稳定读取的短期 COS 签名地址，降低应用服务器本地文件链路导致的抓取失败。
3. 项目卡、聊天记录和前端继续保存稳定的 `/api/assets/file/...` 逻辑地址，不持久化会过期的签名 URL，也不改变当前绝对或相对 URL 格式契约。
4. 保持历史本地图片可读，不进行历史素材迁移。
5. 保持现有保留期限和引用保护语义；用户、项目、任务卡、会话或素材删除后，对应 COS 对象最终被物理删除。
6. COS 上传失败时安全重试并明确失败，不回落到服务器本地磁盘。
7. 删除失败不会被遗忘；系统持久重试、告警和对账，避免 COS 空间无限增长。

## 3. 非目标

- 本次不迁移现有本地图片。
- 本次不迁移生成结果图片；生成结果继续使用当前存储方案。
- 本次不改变现有视频 COS 桶、视频对象前缀或视频密钥权限。
- 本次不接入浏览器直传、STS、CDN、全球加速或数据万象图片处理。
- 本次不把 COS 桶改为公共读。
- 本次不改变各业务模块现有的素材保留时间。

## 4. 已确认的核心决策

### 4.1 独立私有图片桶

创建广州地域独立私有桶 `meiao-managed-images-<APPID>`。所有用户共享一个桶，通过对象前缀和应用层授权隔离，不为每个用户创建单独存储桶。

对象键使用不可猜测的资产 ID，不使用用户输入直接拼接路径：

```text
managed-images/users/<opaque-user-id>/<asset-type>/<asset-id>/<safe-file-name>
```

桶保持私有读写，关闭版本控制。关闭版本控制可避免删除当前对象后仍遗留历史版本占用空间。整个业务前缀不配置统一到期删除规则，因为不同模块的保留期不同；只配置未完成分块上传的自动清理规则。

### 4.2 服务端统一接管

浏览器继续调用现有上传接口。服务端完成身份校验、文件类型和大小校验，再使用腾讯 COS SDK 上传。前端不接触 COS 密钥，也不需要新增 CORS 和 STS 逻辑。

新图片的持久化元数据继续写入 `stored_assets`。其中：

- `provider = 'tencent_cos'`
- `storage_key` 保存 COS 对象键
- `public_url` 继续保存 `/api/assets/file/:assetId/:name` 稳定逻辑地址，并沿用当前绝对或相对格式
- `expires_at` 继续表达现有业务保留时间
- `deleted_at` 继续表达逻辑删除

历史记录继续使用本地 provider。读取层根据 `provider` 选择本地文件或 COS，不要求调用方理解底层存储。

### 4.3 COS-only 上传失败策略

生产环境的新图片上传模式只有 `cos` 和 `disabled`，不提供失败后写入本地磁盘的 fallback。COS 上传对同一个确定对象键执行有限、可配置的安全重试；重试仍失败时返回明确的上传失败提示，用户可以重新上传。

## 5. 组件边界

### 5.1 托管素材存储接口

引入统一存储接口，至少包含：

- `putAsset`
- `createReadUrl`
- `headAsset`
- `deleteAsset`

本地存储和腾讯 COS 分别实现该接口。上传入口、文件读取路由、模型素材解析和清理任务只依赖接口，不直接拼接磁盘路径或 COS URL。

### 5.2 腾讯 COS 图片存储实现

只负责 COS 对象级操作、签名 URL 和错误标准化。它不判断业务引用，不直接修改项目、聊天或任务状态。

### 5.3 素材生命周期服务

负责上传状态、逻辑删除、引用检查、过期判断和清理任务创建。所有删除入口必须通过该服务，禁止业务模块各自直接调用 COS 删除。

### 5.4 持久化清理队列

使用数据库表保存每个待清理对象及重试状态。该队列独立于用户记录，因此注销账号后清理任务仍然存在。

### 5.5 素材读取解析器

前端读取时先校验当前用户是否有权访问素材，再为 COS 对象生成短期签名读取地址并返回 302 重定向。模型调用前也通过统一解析器生成新的短期签名 URL，不复用数据库中的过期地址。浏览器和模型使用不同的签名有效期。

## 6. 数据模型

### 6.1 `stored_assets` 扩展

保留现有字段并增加明确的存储状态，例如：

- `uploading`：数据库已预留资产 ID，COS 上传尚未确认
- `active`：对象存在且可以被引用
- `delete_pending`：已经逻辑删除，等待物理清理
- `deleted`：COS 已确认删除或对象已不存在
- `upload_failed`：上传未成功，禁止读取和引用

新引用只能指向 `active` 素材。状态字段使用向后兼容的字符串列，历史记录迁移时统一视为 `active`。

### 6.2 `asset_cleanup_tasks`

清理任务至少保存：

- 任务 ID 和可空的资产 ID
- provider、bucket、region 和精确 storage key
- 删除原因
- `pending`、`retry`、`in_progress`、`complete` 或 `manual_review` 状态
- 尝试次数、下次尝试时间和最后一次错误摘要
- 创建、更新时间和完成时间

以 provider、bucket、storage key 和动作建立唯一约束，避免重复删除任务。用户外键必须允许用户记录先被删除；任务本身不得保存图片内容和签名 URL。

## 7. 数据流

### 7.1 上传

1. 服务端校验用户、业务模块、文件大小、MIME 和文件头。
2. 在数据库创建 `uploading` 素材记录并生成稳定资产 ID 和 COS 对象键。
3. 使用同一对象键执行 COS 上传；连接错误和结果不明确时可安全覆盖同一键，不会制造多个对象。
4. COS 成功后把素材状态改为 `active`，再向前端返回稳定 `/api/assets/file/...` 地址。
5. 上传失败时把素材标记为 `upload_failed` 并创建幂等清理任务，确保可能已到达 COS 的对象也能被删除。
6. 数据库提交失败或服务重启后，协调器扫描长时间停留在 `uploading` 的记录，确认对象状态并完成提交或清理。

只有第 4 步完成才向用户报告上传成功。

### 7.2 用户或前端读取

1. 请求继续进入 `/api/assets/file/:assetId/:name`。
2. 服务端读取 `stored_assets`，拒绝非 `active`、已删除或无权限的素材。
3. 本地 provider 沿用现有文件服务。
4. COS provider 生成默认 5 分钟有效的签名 GET URL，并通过 302 重定向返回。
5. 签名 URL 不写回项目、聊天、数据库或日志。

### 7.3 外部模型读取

1. 模型提交前解析稳定素材地址。
2. COS 图片生成新的短期签名 GET URL；模型读取默认有效期为 3 小时，并允许通过环境变量保守调整。
3. 将签名 URL 直接交给模型服务读取，避免模型回源应用服务器本地磁盘。
4. 素材稳定与模型服务本身的建连、生成超时、余额和内容策略错误分别监控；迁移 COS 不被视为消除所有 provider 错误。

### 7.4 删除

下列入口统一创建清理任务：单张素材删除、项目删除、任务卡或结果删除、聊天或会话删除、账号注销、素材到期和无引用清理。

1. 在事务中锁定素材记录并检查所有活跃引用。
2. 只有无引用时才标记 `delete_pending` 和 `deleted_at`；新读取和新引用立即被拒绝。
3. 提交数据库事务后，由后台任务按精确对象键调用 COS 删除。
4. COS 删除成功或返回对象不存在均视为幂等成功，再把素材标记为 `deleted`。
5. COS 删除失败时保存错误并按退避策略重试；达到高失败次数后进入 `manual_review` 并告警，但记录不会被丢弃，定时对账仍继续检查。
6. 清理完成的审计记录保留有限时间后自动清除。

账号注销时，清理任务可在用户行删除后继续执行。批量注销不得直接删除整个用户前缀，必须根据数据库列出的精确对象键清理，防止跨用户或跨用途误删。

## 8. 保留规则与防泄漏

- `expires_at` 继续作为业务保留期限的唯一真相。
- 现有默认短期素材保留规则保持不变。
- Agent Center 和 Agent Chat 当前的永久素材语义保持不变，直到用户、会话或账号删除。
- 删除前必须通过统一引用检查；仍被项目、聊天或任务引用的素材不能物理删除。
- COS 桶不设置覆盖全部对象的统一三天生命周期，防止误删长期引用素材。
- 桶级生命周期只负责清除未完成分块上传；业务对象的删除由数据库清理队列驱动。
- 定时协调任务检查长时间 `uploading`、`delete_pending` 和 `manual_review` 记录，防止异常状态静默累积。

## 9. 重试、恢复与错误处理

### 9.1 上传

- 重试次数、单次超时和退避间隔通过环境变量配置，使用保守默认值。
- 所有重试复用同一个资产 ID 和对象键，因此不会生成重复文件。
- 超过上传重试上限后明确返回失败，不在后台偷偷改为成功，也不写入本地。
- 用户重新上传会创建新的资产 ID；旧失败记录由清理队列处理。

### 9.2 删除

- COS 删除是幂等操作；对象不存在等价于清理完成。
- 删除任务持久化，进程退出或发布重启后可以继续。
- 退避重试有最大间隔，但没有“静默放弃并删除记录”的终点。
- 高失败次数、最老待删除时长和队列积压触发告警。
- 每日对账比较数据库状态和 COS 对象存在性，修复任务丢失或状态不一致。

### 9.3 读取

- 签名过期时重新生成，不把过期签名当成素材丢失。
- COS 对象缺失但数据库仍为 `active` 时返回明确内部错误并创建一致性告警，不自动切换到本地同名文件。
- 对用户展示可重试的人话提示，对日志保留错误码、资产 ID 和阶段，但不得记录密钥或完整签名查询参数。

## 10. 安全设计

1. 新建独立 CAM 子用户或独立密钥，不复用视频桶密钥。
2. 权限只覆盖指定图片桶和 `managed-images/*` 前缀所需的 Put、Get、Head、Delete 及受限对账能力。
3. 密钥不得拥有删除桶、修改桶 ACL、修改桶策略或访问其他桶的权限。
4. Secret ID 和 Secret Key 只通过云端环境变量提供，不进入源码、数据库、前端包和日志。
5. 桶为私有读写，只接受 HTTPS；签名地址短期有效。
6. 稳定素材路由继续执行应用层用户授权，不能仅凭资产 ID 越权访问。
7. 文件名经过清洗，对象键由服务端生成；拒绝路径穿越和用户自定义对象键。

建议使用独立环境变量，避免与视频权限耦合：

- `MEIAO_IMAGE_COS_SECRET_ID`
- `MEIAO_IMAGE_COS_SECRET_KEY`
- `MEIAO_IMAGE_COS_BUCKET`
- `MEIAO_IMAGE_COS_REGION`
- `MEIAO_IMAGE_COS_BROWSER_URL_TTL_SECONDS`
- `MEIAO_IMAGE_COS_PROVIDER_URL_TTL_SECONDS`
- `MEIAO_MANAGED_IMAGE_UPLOAD_MODE=cos|disabled`
- 上传重试、超时和清理批次相关环境变量

## 11. 费用与容量保护

- 初期使用标准存储和按量计费，不开启 CDN、全球加速、数据万象和跨地域复制。
- 在腾讯云费用中心设置月度预算，并配置 50%、80%、100% 三档通知。
- 应用记录每日上传字节、活跃 COS 字节、签名读取次数、外网读取量估算、删除积压量和最老待删除时间。
- 观察真实用量后再决定是否购买存储容量包、请求包或外网下行流量包。
- 关闭版本控制，避免删除后保留历史版本。
- 删除和对账阈值必须可配置，不在业务代码中硬编码容量上限。

## 12. 上线与回滚

### 阶段 1：向后兼容基础层

先发布数据库扩展、存储接口、COS 读取能力和清理队列，但保持新上传未启用。这个版本成为后续可安全回滚的基线，必须能同时读取历史本地图片和未来 COS 图片。

### 阶段 2：云资源和探针

创建广州私有图片桶、最小权限 CAM 密钥和云端环境变量。执行一次小文件 `put -> head/get -> signed URL -> delete -> head 404` 探针，并确认对象和密钥仅限目标桶。

### 阶段 3：内部账号灰度

仅给内部测试账号启用 COS 新上传，覆盖项目卡、聊天、洛克买家秀及共用上传入口。执行一次真实外部模型读取验证，并在验证后删除探针素材。

### 阶段 4：逐步全量

按小流量、半量、全量扩大，并观察上传错误率、素材抓取错误率、删除队列和 COS 费用。所有模块共享后端上传入口，因此全量目标按“所有未来用户图片”验收，而不是逐个页面留下不同存储实现。

### 紧急回滚

回滚目标必须是阶段 1 的 COS-aware 版本，保证已上传 COS 的素材仍可读取和删除。紧急情况下把上传模式切为 `disabled`，暂停新图片上传；不得切回本地 fallback。历史素材读取和已有 COS 素材读取继续可用。

## 13. 测试策略

实现阶段对新增或改变的运行时行为使用 TDD。

### 单元测试

- COS 对象键不可猜测且不能路径穿越。
- provider 路由正确区分本地和 COS。
- 签名 URL 每次读取重新生成且不持久化。
- 上传重试始终复用同一对象键。
- COS 上传失败不会调用本地写入。
- 删除成功和对象不存在都幂等完成。
- 删除失败持久化重试，重启后继续。
- 有活跃引用时拒绝物理删除。
- 用户隔离和授权检查不能绕过。

### 集成测试

- 使用可控 COS fake 覆盖 put、head、get URL、delete 和各类失败。
- 覆盖“COS 已成功、数据库提交失败”和“数据库预留成功、进程中断”的恢复。
- 覆盖项目、任务卡、会话和账号删除对清理队列的联动。
- 覆盖历史本地素材和新 COS 素材共存。
- 覆盖 cleanup task 在用户记录删除后继续完成。

### 本地和云上验证

- 运行相关 Node 测试、前端测试、构建和类型检查。
- 运行 doctor、诊断看板 smoke 和静态契约检查，区分既有失败与新增回归。
- 云上执行小图片上传、授权读取、签名读取、模型读取、逻辑删除和物理删除探针。
- 删除后使用 HeadObject 确认对象不存在。
- 检查 PM2、健康接口、错误日志、删除队列和费用指标。

## 14. 验收标准

1. 全量开启后，所有新上传用户图片的 provider 均为 `tencent_cos`，本地资产目录不新增对应备用文件。
2. 历史本地图片继续正常读取，生成结果图片行为不变。
3. 项目卡和聊天持久化稳定 `/api/assets/file/...` 地址，签名 URL 过期后仍能重新读取。
4. 洛克买家秀等外部模型能够读取新的 COS 素材。
5. COS 上传失败时用户收到明确失败，数据库不存在可被业务引用的假成功记录。
6. 删除单张素材、项目、任务卡、会话和账号后，对应 COS 对象最终不存在。
7. 模拟 COS 删除失败和服务重启后，任务仍会继续并最终完成。
8. 清理队列、最老待删除时间和数据库/COS 对账有监控与告警。
9. 前端、日志、数据库和提交历史中均不存在 COS Secret Key 或完整签名 URL。
10. 本地测试、构建、doctor、看板 smoke 和云上灰度验证没有新增失败。

## 15. 实施前置条件

- 腾讯云账号具备创建存储桶和 CAM 最小权限策略的管理权限。
- 云服务器可以安全配置新的图片专用 COS 环境变量。
- 发布流程允许先部署 COS-aware 兼容版本，再启用写入开关。
- 腾讯云费用中心能够配置预算通知接收人。
