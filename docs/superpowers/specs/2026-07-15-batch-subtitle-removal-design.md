# 批量视频去字幕设计

**日期：** 2026-07-15  
**状态：** 已获用户确认，进入实施  
**目标环境：** 本地开发环境完成验收后，另行确认是否发布腾讯云

本规格是 `2026-07-15-video-subtitle-removal-design.md` 的批量增强规格。两者冲突时以本规格为准；其中 Golden `videoName` 的最终合同以当前服务端回归锁定的四段坐标格式为准。

## 1. 背景与目标

现有「视频生成 → 去字幕」工作区从文件选择、草稿状态、区域编辑到任务提交都按单视频建模。用户每处理一个视频都要重新上传、等待分析、占满页面调整区域并单独提交，不适合一次处理多个带字幕视频的真实使用场景。

本次将入口改为“批量任务栏优先”：用户一次上传多个视频，系统逐项准备素材并默认使用画面底部 30% 作为字幕区域。用户只需点开特殊视频调整区域，随后一次确认并提交所有已勾选、已就绪的视频。后台仍为每个视频创建独立耐久任务，但前端把同一次提交聚合为一张批次项目卡。

## 2. 已确认的产品决策

- 页面主体首先展示批量任务栏，上传后不自动把单个视频全屏展开。
- 点击某个任务的「调整区域」才打开响应式编辑弹层。
- 每个视频拥有独立的归一化字幕区域；默认值仍为底部 30%。
- 未点开编辑的视频可直接使用默认区域提交。
- 某个视频上传、分析或转码失败时，不阻塞同批其他已就绪视频。
- 批量提交前显示已选择数、可提交数、异常数、总时长和付费任务数量，并要求一次明确确认。
- 提交后生成一张批次项目卡，卡内逐项展示状态和结果，不为十个视频生成十张顶层卡片。
- 失败项可在原批次中单独重试，不另建重复项目卡。
- 首版每批默认最多 10 个视频；限制由服务端配置并可调整。
- 不自动执行新的真实付费批量冒烟；需要时另行取得明确授权。

## 3. 范围

### 3.1 本次包含

- 多文件选择与拖放上传。
- 批量素材准备队列、逐项真实进度、逐项取消/替换/删除/重试。
- 默认字幕区域与逐项响应式区域编辑弹层。
- 选择状态、准备状态、区域状态和错误状态的任务栏展示。
- 批量提交确认与受控并发创建耐久任务。
- 一个批次项目包含多个独立结果与后台任务身份。
- 批次刷新恢复、混合终态、单项重试、整批删除和结果对比。
- 批量上限、准备并发的服务端配置与公开非敏感能力配置。
- 自动化测试、本地页面验收和相关文档更新。

### 3.2 本次不包含

- 自动识别字幕位置。
- 同一视频提交多个不连续字幕区域。
- 把多个视频合并为一个 Golden 上游任务；Golden 当前仍是一视频一任务。
- 在第三方未提供预报价的情况下展示虚假金额估算。
- 已提交 Golden 后伪造“上游已取消”；接口没有取消能力。
- 未经再次授权执行真实付费批量任务或发布腾讯云。

## 4. 页面与交互

### 4.1 空状态与批量导入

- 空状态保留当前设计语言，上传区支持点击选择和拖放。
- 文件 input 使用 `multiple`，一次选择超过服务端返回的批量上限时整次拒绝，不静默截断。
- 只接受视频文件；单文件时长、大小、编码等继续由 `subtitle_removal` 媒体 profile 权威校验。
- 选中后立即为每个文件创建稳定的本地条目并进入准备队列，不等待整批完成才显示。

### 4.2 批量任务栏

每条任务至少展示：

- 勾选状态。
- 轻量缩略图或视频占位图。
- 文件名、时长、分辨率、大小和编码。
- `等待上传 / 上传中 / 分析中 / 转码中 / 就绪 / 失败 / 提交中` 状态。
- 上传进度或当前处理阶段。
- `默认区域 / 已调整` 区域标记。
- `调整区域 / 重试 / 替换 / 删除` 操作。

任务栏不会同时挂载多个完整播放器。最多只生成轻量预览，删除或替换条目时释放 object URL、AbortController 和媒体临时会话。

### 4.3 区域编辑弹层

- 点击「调整区域」后才挂载 `SubtitleRegionEditor`。
- 桌面端使用与现有系统一致的大尺寸居中弹层；窄屏变为全屏弹层。
- 编辑器按视频真实比例适配，不裁切画面。
- 「保存区域」把归一化区域和像素区域写回对应任务；「取消」保留原区域。
- 保存后关闭弹层并返回此前列表滚动位置。
- 同一时刻只允许一个区域编辑器和一个活跃视频播放器。

### 4.4 底部批量操作栏

- 固定显示：已选择数量、可提交数量、异常数量和已选择视频总时长。
- 「批量开始去字幕」只处理已勾选且就绪的条目。
- 点击后弹出确认层，明确说明将创建多少个独立付费任务；异常和未就绪条目列为未提交项。
- 用户确认后进入提交；重复点击由前端锁和后端稳定提交键双重保护。

## 5. 前端状态模型

将单一 `subtitleRemovalDraft` 扩展为批量工作区状态。每个条目具有稳定身份和独立生命周期：

```ts
type SubtitleRemovalBatchItem = {
  clientItemId: string;
  selected: boolean;
  file?: File;
  draft?: SubtitleRemovalSourceDraft;
  region: SubtitleRemovalRegion;
  regionMode: 'default' | 'custom';
  phase: 'queued' | 'uploading' | 'analyzing' | 'transcoding' | 'ready' | 'submitting' | 'error';
  uploadProgress: number;
  stageText: string;
  errorMessage?: string;
};
```

- 每项 `draftNonce` 和 `clientItemId` 在替换文件时更新，普通编辑不更新。
- 区域变更只作用于对应条目，不广播到其他视频。
- 工作区切换子功能时保留当前批量草稿；页面刷新后的未提交临时草稿不承诺恢复。
- 已提交项目以耐久 job 和共享 app state 为真相，不依赖批量草稿恢复。

## 6. 素材准备队列

- 复用 `createMediaTranscodeSession → convertMediaTranscodeSession`，每个视频有独立 session 和 AbortController。
- 准备队列采用服务端公布的保守并发，默认 2；服务端现有 FFmpeg 全局并发继续作为第二层闸门。
- 兼容 H.264 MP4 不重复转码，不兼容视频保留画幅转换为 H.264 MP4。
- 某项失败只将该项置为 error，调度器继续处理其他 queued 条目。
- 重试只重建该项媒体 session；删除、替换、组件卸载会取消未完成 session。
- 服务端再次校验批量上限，防止绕过前端。

新增配置：

- `MEIAO_SUBTITLE_REMOVAL_BATCH_MAX_ITEMS`：默认 10，限制 1–20。
- `MEIAO_SUBTITLE_REMOVAL_BATCH_PREP_CONCURRENCY`：默认 2，限制 1–4。
- `MEIAO_SUBTITLE_REMOVAL_BATCH_SUBMIT_CONCURRENCY`：默认 2，限制 1–4，只控制前端/服务端创建耐久 job 的节奏，不放宽 provider 和账号并发。

公开系统配置只返回数值限制，不返回令牌或 provider 地址。

## 7. 批量提交与付费安全

- Golden 没有批量 API；每个视频仍创建一个 `subtitle_remove_video` / `golden_subtitle` job。
- 同一次批量提交生成共享 `shellProjectId` 和 `batchId`。
- 每项使用稳定 `shellResultId`、`batchIndex`、`batchCount` 和 `clientSubmissionKey`。
- 批量 job 创建采用小并发，默认不超过 2；provider 真实执行仍受现有账号并发、job 队列和 Temporal worker 控制。
- 任一成功创建的 job 立即成为耐久事实；其余 job 创建失败不会回滚或取消已创建任务。
- 如果创建响应丢失，稳定提交键用于复用已存在的 active job，不能盲目重复提交。
- provider POST 仍保持 `maxRetries=0` 和 Temporal 单次 activity；已有 `providerTaskId` 时只查询旧任务。
- Golden `videoName` 必须继续严格等于 `x1_y1_x2_y2` 四段权威像素坐标，禁止拼入批次或任务前缀。

## 8. 批次项目卡与恢复

- 一批视频形成一个 `module='video'`、`subFeature='subtitle_removal'` 项目。
- 项目 `taskCount` 等于实际准备提交的条目数；每个结果保存自己的 `backendJobId`、源视频、区域、文件名、批次序号和终态。
- `shellDataAdapter` 按 `shellProjectId` 聚合所有去字幕 job，而不是逐 job 生成顶层项目。
- 结果以稳定 `shellResultId` 或逻辑条目身份合并；旧快照不得覆盖新 job 终态。
- 项目卡显示总体进度和成功/失败计数；全部成功显示完成，仍有活动任务显示处理中，终态混合显示“部分完成”。
- 项目共享状态枚举不新增高风险的 `partial` 值；“部分完成”由去字幕批次结果状态派生展示。
- 详情中每个成功结果可打开现有原片/处理结果对比播放器并下载。

## 9. 单项重试与删除

- 失败项在原项目、原结果位置重试，逻辑结果身份不变，新的 backend job 身份替换旧失败尝试。
- 如果 provider 已成功但托管结果保存失败，重试只重新读取旧 provider task 的结果，不创建新付费任务。
- 如果失败终态必须创建新的 Golden 任务，重试前再次明确提示“将产生一次新的付费处理”。
- 活动任务没有 Golden task ID 时遵守现有提交状态未知规则，不允许自动重提。
- 删除整个批次时汇总项目和全部结果中的 backend job ID，写项目墓碑并清理引用。
- 删除页面记录不宣称取消已提交的 Golden 任务；仍在执行的第三方任务依照现有只查询恢复和素材清理规则处理。

## 10. 错误处理

- 批量超限：整次拒绝并说明当前上限。
- 文件不支持：仅对应条目失败，可替换或删除。
- 上传/分析/转码失败：保留可读原因和单项重试入口。
- 部分 job 创建失败：已创建任务继续运行，失败项回到批次项目或工作区等待重试。
- provider 余额不足：对应结果失败，不自动停止已经提交的同批任务。
- provider 提交状态未知：停止自动重提并明确避免重复扣费。
- provider 成功但结果保存失败：展示“处理已完成，保存结果失败”，安全恢复只读取旧结果。

## 11. 测试策略

### 11.1 前端与纯逻辑

- 多文件添加、整批超限、重复文件身份和选择状态。
- 准备队列并发上限、失败不阻塞、删除/替换取消与资源释放。
- 默认底部 30%、逐项自定义区域、取消编辑和横竖屏像素换算。
- 只挂载当前编辑器视频，不让任务栏预加载全部视频。
- 批量确认只统计已勾选且就绪项。
- 重复点击提交被锁定，部分创建成功正确留在批次中。

### 11.2 Job、恢复与项目卡

- 同一批所有 job 使用相同 `shellProjectId`，但有不同稳定结果身份和提交键。
- hydration 把同批 job 聚合为一个项目，刷新后顺序稳定。
- 处理中、全部成功、全部失败和部分完成状态正确。
- 单项重试覆盖旧失败结果，不生成重复顶层项目。
- 整批删除收集全部 backend job ID 并写墓碑。
- provider task ID checkpoint、零重试、旧 ID 查询和结果重抓边界保持不变。

### 11.3 本地验收

- 定向测试和已有去字幕/provider/任务状态回归。
- `npm run doctor`。
- `npm run build`。
- 真实浏览器验证批量列表、区域弹层、不同画幅、部分失败和批次卡恢复。
- 在未取得新授权前只做非付费本地验收；不自动提交 Golden 批量任务。

## 12. 发布与回滚

- 必须先在本地开启真实功能配置完成上述验收，再允许提交、推送或部署。
- 云上发布仍需代码审查和现有排空门禁。
- 新批量配置缺失时使用保守默认；非法值回到默认。
- 功能级回滚继续使用 `MEIAO_SUBTITLE_REMOVAL_ENABLED=0`，只禁止新任务，不隐藏历史批次和结果。

## 13. 成功标准

- 用户一次导入多个视频后首先看到任务栏，而不是单视频全屏编辑器。
- 未调整的视频可直接使用默认底部 30% 区域。
- 特殊视频可以逐项点开、适配画幅调整并返回原列表位置。
- 单个坏文件不会阻塞同批其他视频。
- 一次确认可创建多个独立耐久任务，并明确告知任务数量和付费性质。
- 刷新后同批任务仍聚合为一张项目卡，混合终态可读，失败项可安全重试。
- 不重复付费提交，不泄露令牌，不破坏现有单视频结果和对比播放能力。
- 本地真实页面、测试、doctor 和 build 全部通过后才进入云上发布流程。
