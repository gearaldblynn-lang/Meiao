# 产品还原逐图提示词协议设计

## 1. 背景与结论

本设计修订 [`2026-07-14-image-upgrade-product-restoration-design.md`](./2026-07-14-image-upgrade-product-restoration-design.md) 中“分析模型生成一条整批共用提示词”的约定。产品还原仍采用一次分析、逐图生图的两阶段工作流，但分析结果必须为每张待还原图提供一条独立、可直接执行的修改生图提示词。

2026-07-15 本地真实任务 `0ed6fd04f12c996ba488d169` 同时暴露了两个问题：

1. 上游返回了符合旧字段结构的 JSON，但在 JSON 后附加了 `final_answer`，旧解析器对全文直接执行 `JSON.parse`，因此错误标记为 `product_restore_analysis_invalid`。
2. 即使去除尾标后能够解析，旧协议仍只会把一条 `sharedRestorationPrompt` 复制给所有待还原图，无法表达每张图不同的产品偏差和保护边界。

本轮采用已确认的方案 A：一次分析调用读取全部待还原图和产品参考图，返回公共产品真值以及与每张待还原图一一对应的独立提示词；随后每张待还原图只使用自己的提示词创建一个生图任务。

## 2. 目标与非目标

### 目标

- 分析模型只调用一次，分析模型继续跟随程序设置，不增加用户选择入口。
- 每张待还原图必须得到一条独立提示词，数量和顺序与待还原图严格对应。
- 每条提示词描述当前图的实际偏差、需要修改的产品特征和必须保持的非产品内容。
- 每个生图任务只接收当前待还原图、同一组产品参考图和当前图自己的提示词。
- 分析结果、目标素材身份和逐图提示词映射必须持久化，刷新恢复和单张重试不重新分析。
- 解析器容忍已确认的 provider 包装噪声，但继续拒绝未知尾文、缺字段、重复序号和数量不匹配。
- 使用当前本地素材完成一次真实分析和一次真实生图，检查最终图片与原图、参考图之间的差异。

### 非目标

- 不把分析模型暴露给用户选择。
- 不为每张待还原图额外调用一次分析模型。
- 不在分析失败时回退为通用提示词或普通精修，避免错误扣费和错误产品结果。
- 不改变产品还原的上传上限、重点还原选项、生图模型、2K/4K 规则和原始比例继承规则。
- 不部署腾讯云；本轮只修改并验证本地开发环境。

## 3. 方案比较

### 方案 A：一次分析返回逐图提示词（采用）

一次分析同时建立产品公共真值，并为每张待还原图返回独立提示词。分析成本和延迟固定，且能够利用全套参考图判断每张目标图的差异。

### 方案 B：公共分析后逐张再分析

先分析产品真值，再为 N 张待还原图创建 N 个提示词分析任务。针对性强，但会增加 N 次分析费用、失败点和等待时间，不采用。

### 方案 C：程序从公共分析拼接提示词

只让模型输出公共产品分析，由程序把同一组字段拼进每张图。成本最低，但程序无法识别每张图不同的偏差，仍会退化为旧的通用提示词，不采用。

## 4. 分析输出协议 V2

分析模型必须只输出下列结构的 JSON：

```json
{
  "version": 2,
  "productIdentitySummary": "由产品参考图验证的产品身份摘要",
  "invariantFeatures": [
    "全部结果都必须保持的产品身份特征"
  ],
  "targetPrompts": [
    {
      "targetIndex": 1,
      "targetIssueSummary": [
        "待还原图 1 相对参考产品存在的可验证偏差"
      ],
      "restorationPrompt": "仅针对待还原图 1 的完整修改生图提示词"
    }
  ]
}
```

字段约束：

- `version` 必须严格等于 `2`。
- `productIdentitySummary` 必须为非空字符串。
- `invariantFeatures` 必须为字符串数组，可为空但不得缺失。
- `targetPrompts` 必须为数组，长度严格等于待还原图数量。
- `targetIndex` 必须是从 `1` 到 `N` 的整数，且不得缺失、重复或越界。
- `targetIssueSummary` 必须为字符串数组，可为空但不得缺失。
- `restorationPrompt` 必须为非空字符串，并且是当前图可以直接交给生图模型的完整修改指令。

每条 `restorationPrompt` 必须包含：

- 当前图中产品本体需要修复的具体差异；
- 参考产品中必须还原的形态、结构、比例、材质、纹理、颜色、光泽、Logo/文字、部件或工艺事实；
- 当前图中产品数量、位置、视角、大小、遮挡和接触关系的保护规则；
- 当前图中背景、人物、版式、营销文字、装饰、裁切和构图的保护规则；
- 保持原始比例、禁止重构画面、禁止引入参考图场景元素的要求；
- 用户选择的重点还原项和补充要求，但用户要求不得覆盖产品真值和固定保护规则。

`targetIndex` 只用于分析模型输出。程序解析后立即按当前目标图顺序把它转换为稳定的 `targetMaterialId`，后续持久化、刷新恢复和单张重试不得依赖数组位置猜测身份。

## 5. Provider 包装与解析规则

解析器按以下顺序处理返回文本：

1. 去除首尾空白。
2. 如果全文由一个 `json`/无语言 Markdown 围栏包裹，去除这一层围栏。
3. 提取一个完整 JSON 对象。
4. JSON 对象之后只允许空白或已确认的独立 provider 尾标 `final_answer`。
5. 任何其他前导说明、尾部说明、第二个对象或未知文本都视为无效，不做宽松猜测。
6. JSON 解析后执行 V2 字段、目标数量、序号完整性和非空提示词校验。

错误应区分：

- `product_restore_analysis_invalid`：不是可安全解析的 V2 JSON。
- `product_restore_analysis_target_prompts_invalid`：JSON 可解析，但逐图提示词数量、序号或内容不符合合同。

任何一种错误都必须发生在第一个生图任务创建之前。不得自动使用旧的共享提示词继续扣费生图。

## 6. 持久化上下文与兼容

新任务持久化 `ProductRestoreProjectContext` V2：

```ts
interface ProductRestoreTargetPrompt {
  targetMaterialId: string;
  targetIndex: number;
  targetIssueSummary: string[];
  restorationPrompt: string;
}

interface ProductRestoreProjectContextV2 {
  version: 2;
  analysisJobId: string;
  analysisProviderTaskId?: string;
  analysisModel: string;
  analysisCreditsConsumed?: number;
  productIdentitySummary: string;
  invariantFeatures: string[];
  targetPrompts: ProductRestoreTargetPrompt[];
  focusIds: ProductRestoreFocusId[];
  targetMaterialIds: string[];
  productReferenceMaterialIds: string[];
  selectedImageModel: string;
  resolution: '2K' | '4K';
  userRequirement: string;
  createdAt: number;
}
```

新分析任务和新生图任务的幂等键使用 `v2`，避免与旧协议任务混淆。

兼容策略：

- 已失败且没有持久 V1 分析上下文的任务，允许用户重新分析并生成 V2 上下文。
- 已存在完整 V1 上下文的历史项目继续可查看；历史单张重试仍复用其原 `sharedRestorationPrompt`，不静默改变历史付费任务语义。
- 所有新建和重新分析任务只产生 V2，不再产生新的 `sharedRestorationPrompt`。
- V1/V2 分流必须由结构化 `version` 判断，禁止按字段存在或提示词文本猜测。

## 7. 逐图任务编排

V2 分析成功后：

1. 按 `targetIndex` 排序并映射到 `targetMaterialIds[targetIndex - 1]`。
2. 在创建任何生图任务之前，先持久化完整 V2 上下文。
3. 对每张待还原图创建一个生图任务，输入顺序固定为：当前待还原图、全部产品参考图。
4. 动态提示词只取该 `targetMaterialId` 对应的 `restorationPrompt`，不得回退到另一张图或公共提示词。
5. 程序在动态提示词外层保留固定的 RTCFE 安全保护合同，保证非产品区域、原始比例和产品真值约束不能被模型输出或用户补充要求取消。
6. 生图结果的 `prompt`、任务 payload 和项目详情均保存当前图的最终有效提示词，便于排查和对比。
7. 单张重试按 `targetMaterialId` 读取原提示词，只创建该图的新生图任务，不重新分析、不修改其他图片状态。

如果找不到当前目标图的唯一提示词，必须返回 `product_restore_target_prompt_missing`，且不得提交 provider。

## 8. RTCFE 分析提示词要求

分析 prompt 继续遵守 `docs/prompt-rtcfe-migration-map.md`：

- R：电商产品一致性分析师与逐图修改提示词工程师。
- T：从产品参考图建立产品真值，并逐张比较待还原图，输出 V2 JSON。
- C：参考图只提供产品身份；待还原图决定构图和非产品内容；每张提示词只能修改当前图产品本体；不得编造不可验证信息。
- F：只输出 V2 JSON，`targetPrompts` 数量和序号与待还原图严格一致。
- E：示例只展示字段和序号，不携带可被照抄的品牌或产品事实。

程序不再根据公共分析字段生成通用动态提示词。动态提示词的逐图差异必须由分析模型明确输出。

## 9. 状态、错误和积分

- 分析 job 成功但协议无效时，项目显示分析结果不可用，不创建生图 job。
- 已发生的分析积分按真实 job 台账保留；重新分析会产生一次新的分析尝试和对应积分。
- V2 上下文未完成权威持久化时不得开始 fanout。
- 任一图片生成失败不影响其他已创建图片任务，批次保持现有部分完成语义。
- 刷新恢复以服务端 canonical state 和耐久 jobs 为真相；不能只在 React 内存中保存逐图提示词。
- 日志记录 V2 版本、目标数量、提示词映射是否完整、目标素材 ID 和任务 ID；不打印签名素材 URL、密钥或完整图片二进制。

## 10. TDD 与回归范围

必须先增加失败测试，再修改生产代码：

1. 真实旧响应 fixture：合法 JSON 后带 `final_answer`，解析应成功。
2. 未知尾文、前导解释、第二个 JSON 对象仍应失败。
3. `targetPrompts` 缺失、数量不符、序号重复、越界、提示词为空应在生图前失败。
4. 两张目标图返回两条不同提示词时，两个生图调用分别收到各自提示词。
5. V2 上下文按 `targetMaterialId` 持久化，刷新和单张重试仍使用同一提示词。
6. V1 历史上下文保持只读和既有单张重试兼容。
7. 上下文持久化失败时，生图调用数必须为零。
8. 取消、重试、积分合并和项目卡水合不能因 V2 上下文回退。

定向测试通过后还需运行 TypeScript、构建、`doctor` 和产品还原相关回归集。

## 11. 当前素材的本地真实验收

验收继续使用当前已持久化的素材：

- 待还原图：1 张三步教学版式沙发盖布图片；
- 产品参考图：3 张绿色人字形/鱼骨纹沙发盖布图片；
- 重点还原：材质与纹理；
- 用户补充要求：主要还原沙发布的纹理以及质感；
- 生图模型：GPT Image 2；
- 分辨率：2K；
- 比例：自动继承待还原图原始比例。

真实验收步骤：

1. 用 V2 分析提示词创建一次新分析任务。
2. 检查分析 job 成功、V2 JSON 可解析、`targetPrompts.length === 1`，并持久化到目标素材 ID。
3. 检查只创建一个生图任务，输入为当前待还原图和 3 张产品参考图，prompt 为该目标图的独立提示词。
4. 等待真实结果落入站内托管地址，并验证可读取、尺寸至少达到所选 2K 档且比例与原图一致。
5. 对比原图、参考图和结果图，至少检查：
   - 沙发盖布的人字形/鱼骨纹理更清晰、连续且有立体起伏；
   - 面料呈现厚软、轻绒感和自然垂坠；
   - 橄榄绿/苔绿色与同色流苏身份保持；
   - 三步教学版式、日文文字、数字圆标、室内背景、家具、人物、视角、裁切和构图未被主动重设计；
   - 没有引入参考图中的窗户、摆件、靠枕、桌子或装饰画。
6. 刷新页面，确认项目、逐图提示词和结果仍可恢复；对已完成结果不自动再次提交。

本轮真实验收授权范围为一次新分析任务和一次新生图任务。若链路成功但画质仍未达到上述标准，应保留全部证据并报告具体偏差，不自动创建第二个付费生图任务。

## 12. 完成判据

- 新协议不再产生整批共用动态提示词。
- 分析输出与待还原图形成严格的一对一映射。
- 本次 `final_answer` 包装可安全解析，未知包装仍 fail closed。
- 每个生图任务使用当前图自己的提示词和同一组产品参考图。
- 刷新、恢复、取消和单张重试保持状态与积分一致。
- 自动化测试、TypeScript、构建和本地健康检查通过。
- 当前素材完成一次真实分析和真实生图，并交付原图/参考图/结果图的对比结论及任务证据。
