# 短视频 `@素材` 引用设计

日期：2026-07-20  
状态：用户已确认实施  
适用范围：短视频生成 → 全能参考

## 1. 目标

在短视频“全能参考”输入器中增加与即梦 / Seedance 2.0 语义一致的 `@素材` 能力：

- 输入 `@` 或点击 `@素材` 按钮，只从当前任务已上传的图片、视频和音频中选择。
- 将选中项以 `@图片1`、`@视频1`、`@音频1` 等易读文本插入提示词。
- 引用在素材新增、删除或分组顺序变化后仍绑定原素材，不会静默指向另一个文件。
- 对 KIE、MaxForAI 和即梦 CLI 沿用现有提示词与三类有序 URL 数组，不新造上游不支持的 mention 字段。

## 2. 官方协议结论

Seedance 2.0 公开提示词规范通过 `@图片N`、`@视频N`、`@音频N` 表达引用，素材内容通过各模态的有序数组传入。KIE 和 MaxForAI 的公开请求字段同样只包含提示词以及图片、视频、音频数组，没有独立的引用映射字段。

因此，“可稳定绑定的 `@素材`”必须由梅奥内部完成两层转换：

```text
界面引用（稳定 materialId）
  -> 提交时引用清单（当次数组真实顺序）
  -> 上游提示词 @图片N/@视频N/@音频N + 有序 URL 数组
```

## 3. 范围与非目标

### 3.1 本次包含

- 仅在“短视频生成 → 全能参考”显示 `@素材` 交互。
- 候选素材仅来自当前输入区的 `product`、`scene`、`referenceVideo`、`audio`。
- 支持键盘输入 `@`、按钮打开、文字过滤、上下键选择、Enter 插入、Escape 关闭。
- 支持图片缩略图、视频/音频类型标识、文件名和引用名称。
- 任务 payload 保存编译后提示词与引用清单，用于排障、恢复和审计。

### 3.2 本次不包含

- 不搜索历史素材库、已生成结果或跨项目素材。
- 不在“首尾帧”或“智能多帧”中开放 `@`；这两种模式保持既有位置契约。
- 不替换当前 textarea 为完整富文本编辑器。
- 不修改 provider 创建、轮询、重试、计费或素材转存逻辑。

## 4. 方案比较

### 方案 A：只在提示词中插入当前序号

优点是改动最小。问题是新增或删除前面的素材后，原有 `@图片2` 会指向其他文件，属于静默语义错误，不可采用。

### 方案 B：完整富文本 mention 编辑器

优点是 mention 可以成为不可拆分的彩色标签。问题是需要重做输入、选区、粘贴、IME、撤销、移动端和历史 prompt 兼容，风险明显高于本次需求。

### 方案 C：文本 mention + 稳定绑定元数据 + 提交时编译（采用）

保留现有 textarea 和普通文本体验，同时为通过菜单插入的引用记录稳定 `materialId`。提交时以当次实际素材顺序编译 provider 编号。它兼顾稳定性、历史文本兼容和实施风险。

## 5. 界面与交互

### 5.1 打开菜单

- 用户在 textarea 中输入 `@` 时，在输入区上方打开候选菜单。
- `@` 后继续输入可按文件名、类型或引用名过滤。
- 工具栏增加 `@素材` 按钮，用于鼠标或触摸操作；点击后在当前光标位置插入。
- 无可用素材时，按钮保留但菜单提示“请先上传图片、视频或音频素材”。

### 5.2 候选项

按模态分三组显示，但编号是模态内独立的：

- 图片：`product` 在前，`scene` 在后。
- 视频：`referenceVideo` 原顺序。
- 音频：`audio` 原顺序。

已经有稳定绑定的素材继续显示原引用名；尚未引用的素材显示当前候选名。同一素材多次插入时复用同一引用名。

### 5.3 插入与编辑

- 选中候选项后，用引用文本替换当前 `@查询`，并在后面自动补一个空格。
- 插入后恢复 textarea 焦点，光标放在引用之后。
- 用户仍可手动编辑、删除或粘贴提示词。
- 用户手工输入但未建立稳定绑定的 `@图片N/@视频N/@音频N` 保持官方顺序语义，作为兼容路径。

## 6. 内部数据契约

绑定数据作为当前表单参数持久化，不改写全局 Material 公共类型：

```ts
type VideoMaterialMentionBinding = {
  label: string;                 // @图片1 / @视频1 / @音频1
  materialId: string;            // 梅奥内部稳定素材 ID
  kind: 'image' | 'video' | 'audio';
  sourceType: 'product' | 'scene' | 'referenceVideo' | 'audio';
};
```

- `currentParams.videoMaterialMentionBindings` 保存受限 JSON 数组。
- 解析时严格限制数量、字段长度、模态和来源类型，忽略非法或重复项。
- 绑定的显示 label 在当前表单生命周期内不复用，防止旧 prompt 重新指向新文件。
- 任务 payload 另保存 `videoReferenceManifest`，记录提交快照中的 `materialId/kind/sourceType/providerOrdinal/label`，不记录额外密钥或签名信息。

## 7. 提交时编译

在 `runShellVideoGeneration` 创建内部 job 之前，用同一个纯函数同时构建三件东西：

1. 当次有序素材清单。
2. 上游可读提示词。
3. 可审计的 `videoReferenceManifest`。

编译规则：

- 图片 provider 顺序仍是 `product + scene`，视频和音频仍保持各自数组顺序。
- 对每个出现在 prompt 中的已绑定 label，通过 `materialId` 找到其当次 provider 序号，并将 label 改写为 `@图片N/@视频N/@音频N`。
- 未绑定的官方文本引用不改写，继续按当次数组顺序解释。
- 编译只修改提交快照，不回写用户编辑框，避免光标跳动或历史文本被惊讶改写。
- 编译后提示词和同一快照的 URL 数组一起写入 job，后续 provider 不再重排。

## 8. 异常和降级规则

- prompt 仍引用已删除素材：提交前拦截，明确提示“`@图片N` 对应素材已移除，请删除该引用或重新选择素材”。
- prompt 引用的素材尚无可提交 URL：在付费 provider 创建前拦截，提示等待上传完成或重新上传。
- 绑定 JSON 损坏：不阻断页面渲染，忽略非法数据；手工 `@N` 仍按官方顺序语义工作。
- 上游不接收新的内部绑定字段；provider adapter 只收到编译后 prompt 和原有 URL 数组。
- 不新增模型降级、不切换 provider、不因 mention 错误自动创建第二个付费任务。

## 9. 兼容与安全

- 旧 prompt 和旧项目没有绑定元数据时保持原行为。
- 引用数据仅能指向当前表单中的素材 ID，不允许通过客户端 JSON 注入额外 URL。
- 服务端继续以现有受管素材、owner context 和 URL 解析为权威，manifest 不绕过素材权限。
- 提交编译发生在任何付费 provider POST 之前，错误时不扣费、不创建上游任务。

## 10. 测试与验收

至少覆盖：

1. 图片、视频、音频候选顺序与独立编号。
2. 同一素材重复插入复用绑定。
3. 在前方新增或删除素材后，提交编译仍指向原 `materialId`。
4. 已引用素材删除、URL 未就绪、损坏 JSON 和重复绑定。
5. 手工 `@N` 与历史 prompt 兼容。
6. `@` 查询替换、光标位置、键盘导航、IME 和 Escape。
7. 仅全能参考显示，首尾帧、智能多帧及其他模块不回归。
8. KIE、MaxForAI、即梦 CLI 三条路径都收到一致的编译提示词和有序数组。
9. 任务 payload 含有不带秘密的引用 manifest，provider payload 不泄漏内部绑定 JSON。

定向测试后运行：

- TypeScript 检查与 ESLint。
- 影响面相关 Node 测试和完整 `npm run verify`。
- `npm run doctor`。
- 浏览器实测默认视口和窄屏，验证菜单、键盘操作、提交前错误和任务请求。
- 三个 provider adapter 用本地仿真请求验证字段与顺序；不为验证 UI 新功能额外创建三笔付费任务。

## 11. 验收标准

- 全能参考上传任意图片、视频或音频后，输入 `@` 可选中当前素材并插入可读引用。
- 素材顺序变化时，上游提示词的实际编号自动编译到原素材。
- 已引用素材失效时在付费提交前明确拦截，不静默换素材、不切换模型、不二次创建。
- KIE、MaxForAI 和即梦 CLI 不新增非公开字段，现有任务恢复与计费契约保持不变。
