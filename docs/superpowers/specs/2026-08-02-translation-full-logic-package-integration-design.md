# 出海翻译完整逻辑包本地集成设计

## 目标

将 `/Users/feiyanglin/Downloads/出海翻译完整逻辑包_2026-07-31` 中相对当前版本新增的出海翻译合同完整合入主程序，同时保留当前工作树已经存在的区域修改、受保护素材、任务终态、水合恢复、权限和 provider 修复。

初始集成阶段只做本地集成和验证。2026-08-02 本地验收完成后，用户另行明确批准提交 Git、推送和腾讯云发布；发布必须继续通过仓库标准代码审查、任务排空和云上验收门禁。

## 方案选择

采用三方合同合并：

1. 以当前工作树为运行基线。
2. 以包内设计和测试为行为合同。
3. 仅移植包内新增的函数和当前实现缺少的接线。

明确不采用：

- 整包覆盖：包内大型共享文件来自另一份较旧快照，会回退当前版本修复。
- 平行功能开关：会留下两套策划和持久化合同，增加后续漂移风险。

## 行为范围

### AI 优化策划

- 目标语言映射到默认通用电商市场。
- 策划角色改为目标市场母语电商本地化文案总监。
- 同语种输入仍检查自然度，但自然、准确的文案允许原样保留。
- 不使用固定 `80%-120%` 字符限制。
- 保持 RTCFE、`“原文”本地化为“目标文案”` 和 `“文字”保持不变` 解析锚点。
- 规范化模型输出，只把结构化映射和保持项送入后续流程。

### 目标语言守卫

- 聚合映射右侧成品文案，保守检查明显的文字体系冲突。
- 第一次明确冲突时纠错重试一次。
- 第二次仍冲突时抛出 `translation_target_language_mismatch`，停止生图。
- 两次策划积分相加，保留所有策划任务 ID。
- 自定义语言、短品牌名、数字和共享汉字保守放行。

### 批次一致性

- 每个原始翻译批次创建一个共享注册表。
- 完全相同的原文经 NFKC 和空白规范化后复用首个已接受译文。
- 相似但不完全相同的原文不合并。
- 重试任务保持单图独立，不跨历史批次复用。

### 生图

- AI 优化结果逐字照抄，不允许图像模型再次翻译或润色。
- 加强原图尺寸比例、构图、商品、字体层级、背景融合和非目标元素保护。
- AI 直出流程不经过策划、语言守卫或批次注册表，现有行为保持不变。

### 项目展示

- 新翻译项目使用 `M月D日 项目N 子功能·X张`。
- 序号按本地日期和翻译子功能分别计算。
- 展示层对已有翻译项目名称做纯函数规范化，不修改持久化历史数据。
- 任务 fallback 占位项目不参与重新编号。

## 数据流

```text
提交
  -> 创建配置快照和可见项目
  -> 每图 AI 优化策划
  -> 结构化结果规范化
  -> 目标文字体系守卫（最多一次纠错重试）
  -> 同批原文一致性协调
  -> 构建逐字照抄生图 Prompt
  -> 现有 kie_image 任务链
  -> 现有结果托管、状态写回和水合
```

## 兼容边界

- 不修改 `translationEditProcessingMode`、`user_cancelled`、`client_output_rejected` 等区域修改终态。
- 不修改原图尺寸 fail-closed、provider 身份恢复、计费和托管资产逻辑。
- 不引入依赖、环境变量、数据库迁移或新的 UI 控件。
- 不从包内覆盖 `ShellMigratedApp.tsx`、`arkService.ts`、`providerGateway.mjs` 等共享文件。
