## 2. 用户可见能力

### 2.1 模特替换

- 模块归属固定为：
  - `module: everything_replace`
  - `subFeature: model_replace`
- 身份来源支持：
  - `upload`：临时上传 1–4 张同一人物图片。
  - `library`：选择一个已发布虚拟模特的精确版本。
- 支持 1–40 张待替换参考图，一张参考图对应一个独立结果。
- 支持：
  - `identity_only`：替换身份、肤色、头发等身份特征，保留参考图姿势、
    服装、配饰和人物关系。
  - `full_person`：以主身份图为人物来源，同时硬保护参考图中的商品、
    Logo、文字、构图、光影和画幅。
- 提交前完成数量、单人、身份一致性、脸部可用性、人物尺寸和参考图姿态
  分析；预检失败不得创建项目或付费生成任务。
- 批量生成允许部分成功；单项重试只替换目标失败结果，不覆盖同项目已成功
  结果。

### 2.2 虚拟模特库

- 只有管理员能看到入口并执行写操作。
- 管理员可创建模特资料、创建版本、绑定八个固定角度素材、发布、下架和
  软删除。
- 八槽位固定为：
  - `front_close`
  - `left_45_close`
  - `right_45_close`
  - `profile_close`
  - `front_half`
  - `three_quarter_half`
  - `front_full`
  - `three_quarter_full`
- `front_close` 是唯一主图；只有八槽位完整、身份档案存在、所有素材校验
  通过时才能发布。
- 已发布版本不可修改；更新模特必须创建新版本。
- 普通用户只能读取已发布模特的公开摘要并按名称、编号和标签选择。
- 下架或删除后不能创建新任务，但已有任务仍可按原版本和原素材顺序重试。

## 3. 架构与边界

### 3.1 分层集成

按以下顺序落地，每层拥有独立测试：

1. 虚拟模特存储、八槽位规则、MySQL/本地 JSON 双路径。
2. HTTP API、管理员权限、永久素材和预览图。
3. 服务端可信任务快照、历史素材解析、provider 输入顺序和计费。
4. 前端 API 客户端、管理员管理页、普通用户选择器。
5. 模特替换预检、RTCFE 提示词、生成工作流。
6. 主壳接线、持久化、刷新恢复、项目卡和单项重试。

专属文件按原相对路径合入；`server/index.mjs`、
`src/ShellMigratedApp.tsx` 等共享文件只迁移目标符号和分支。

### 3.2 身份来源互斥

上传草稿和模特库选择草稿可各自保留，但一次提交只能读取当前激活来源：

- `upload` 只使用临时 `model` 素材。
- `library` 不使用客户端临时身份素材，也不接受客户端提供的模特素材 URL、
  身份描述或任意素材 ID。

两个来源最终都进入同一模特替换预检、逐图生成、项目持久化和单项重试
生命周期。

### 3.3 服务端信任边界

- 新任务使用 `{virtualModelId, virtualModelVersionId}` 重新解析已发布版本。
- 服务端根据参考图分析选择三张最匹配的身份素材；默认选择正面、左 45 度、
  右 45 度近景。
- provider 输入顺序必须是身份图在前、当前参考图最后。
- 任务保存白名单化不可变快照，包括精确版本、发布时间、选中素材 ID 和
  槽位顺序。
- 历史重试按原快照解析，不自动切换到新版本。
- 管理员鉴权必须发生在读取写请求 body 之前。
- 公共响应不得包含身份档案、创建人、内部路径或源素材私有元数据。

### 3.4 素材生命周期

- `virtual_model` 加入永久资产模块，不参与普通临时素材过期清理。
- 绑定槽位时验证素材归属、图片类型和模块名。
- 服务端生成 480×640 JPEG 预览。
- 删除使用软删除；历史版本和已引用素材继续保留。

## 4. 状态、持久化与错误

- 项目继续使用 `shellProjects`，不新增独立前端 memory 数据块。
- generation context 深拷贝并白名单保存：
  - `identitySource`
  - `virtualModelSnapshot`
  - `preflight.referenceAnalysis`
  - `replacementScope`
  - 原始输入顺序和批次索引
- 数据适配器必须把 `model_replace` 识别为合法子功能，不允许默认为其他
  万物替换页签。
- 项目卡只显示公开模特名称、编号和版本。
- 业务失败保留结构化错误码；未知服务端错误收口为
  `MODEL_REQUEST_FAILED`，不向客户端暴露数据库或文件路径。
- 模特库失效、素材缺失或快照不一致时 fail closed，不创建新付费任务。
- 已存在 `providerTaskId` 的任务只能查询或恢复，不能二次创建。

## 5. Prompt 与生成合同

- 模特替换使用独立 RTCFE 提示词，不拼接产品替换中“重绘为不同人物”的
  规则。
- R：电商视觉模特替换执行模型。
- T：按 `identity_only` 或 `full_person` 完成人物替换。
- C：身份图是唯一身份来源；参考图商品、Logo、文字、颜色、材质、结构、
  构图和画幅受保护；用户补充要求优先级低于这些硬规则。
- F：只输出一张完整商业效果图，不输出分析文字、蒙版、拼贴或对比图。
- E：两种替换范围各保留一个不引入额外业务事实的最小示例。
- 提示词中的图片编号根据真实输入数组计算，禁止固定写死。
- 防止已编译提示词在 provider 层被再次嵌套。
