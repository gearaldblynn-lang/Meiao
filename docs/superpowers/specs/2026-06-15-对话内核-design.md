| 能力 | 现状 | 缺口 |
|---|---|---|
| 多轮历史 | 后端 `buildProviderInputMessages`/`resolveProviderMessages` 已接收并转发 `messages` 数组 | 历史**原样全量**发给模型,**无任何裁剪/压缩**(grep 仅有字符串 `.trim()`,无窗口管理) |
| 会话/消息存储 | 已有 `/api/chat/sessions`、`/api/chat/agents`,前端 `AgentChatSession`/`AgentChatMessage`,按用户隔离 | 完整,可复用 |
| 多模型 | `providerGateway` 已登记 `gpt-5-2`/`gpt-5-4`/`claude-sonnet-4-6`/`gemini-3.1-pro` 等,走中转站 | 缺"每个模型上下文多长"的能力表 |

**结论:四个缺口——① 上下文管家 ② 模型能力表 ③ 流式输出 ④ 实时状态。地基全在,补这四样即可。**

## 2. 设计

四个新单元,每个职责单一、可独立测试。

### 2.1 模型能力表(单一来源)
- 新增 `server/modelCapabilities.mjs`:一张表,key = 模型 id,value = `{ contextWindowTokens, maxOutputTokens, supportsStreaming, supportsToolUse }`。
  - `supportsToolUse` 本期不用,先登记,给第2期生图留位。
- 提供 `getModelCapability(modelId)`:命中返回该模型能力;未登记返回**保守默认**(小窗口 + 不假设支持流式),并 `log` 一条"模型未登记"提醒(呼应"缺数据不阻塞、给保守默认"铁律)。
- 这是"换模型自动适配"(用户已选方案)的唯一数据源。

### 2.2 上下文管家(本期核心,纯函数)
- 新增 `server/contextWindow.mjs`,导出纯函数 `planContextWindow({ messages, modelId, reserveOutputTokens })` → 返回**要实际发给上游的 messages**(不改入参,不写库)。
- 策略(全部基于 token 计数 + 轮次序号,**不用正则猜语义**):
  1. 估算每条消息 token(字符数 → token 的保守换算,中英分别系数,宁可高估)。
  2. system 提示永远保留。
  3. 预算 = `contextWindowTokens − reserveOutputTokens − 安全余量`。
  4. 从最新一轮往回累加,保留尽可能多的**最近原文**轮次。
  5. 超预算的较早轮次,**压缩成一段摘要**(调一次便宜模型生成摘要),作为单条 system/assistant 摘要消息插在最近原文之前。
  6. 触发阈值(开始压缩的占用百分比)、保留多少轮原文、摘要用哪个模型 —— 全做成 env + 保守默认。
- 摘要产物只存在于"本次发送",**不回写原始 `messages`**。可选:把摘要缓存到会话级字段以省重复摘要开销,但缓存≠覆盖原文(此优化列为可选,不做也达标)。
- **压缩对用户可见(业主决定 2026-06-15):压缩发生时,前端必须给一个轻量提示**(如在消息流中插一条"较早的 N 轮对话已折叠为摘要"的系统提示行),让用户知道发生了什么、为什么模型"看起来记得但不是逐字记得"。提示是展示层信息,不写回原始历史。

### 2.3 流式输出
- 对话链路新增流式路径:上游 `stream: true` → 后端边收边通过 SSE 推前端 → `AgentCenterModule` 增量渲染"逐字蹦出"。
- **非流式路径保留原样**,生图等其它模块继续走旧路,零回归。
- 上游不支持流式的模型(查能力表 `supportsStreaming`)自动回退非流式,前端表现为"整段到达"。

### 2.4 实时状态
- 复用已有 `/api/chat/progress/{id}`,定义本期对话状态事件:`thinking`(已收到、模型在想)→ `streaming`(正在逐字返回)→ `done` / `error`。
- **上下文压缩提示**:压缩触发时,通过同一通道告知前端,前端在消息流插入"较早 N 轮已折叠为摘要"的提示行(见 2.2)。
- 本期状态**仅限对话本身**;生图、调知识库等状态是第2/3期再往这个通道加,不在本期。
- 前端在 AgentCenter 把这些状态实时显示在消息区。

## 3. 数据流(一轮对话)

```
用户发消息
  → 前端把整段会话历史 + 选定模型 发给后端对话端点
  → 后端 planContextWindow(历史, 模型) ── 超长则压缩较早轮次为摘要 ──► 实际要发的 messages
  → providerGateway 带 stream:true 调上游(查能力表决定是否真流式)
  → SSE 把增量 token + 状态事件 推回前端
  → 前端逐字渲染 + 实时状态;原始历史照常入库(摘要不回写)
```

## 4. 错误与兜底
- 上游超时/限流/抖动:复用现有重试退避(`jobRuntime` 既有模式),流式中断给前端明确 `error` 状态,不污染会话数据。
- 模型未登记:走保守默认能力,不崩。
- 摘要调用失败:降级为"只保留最近原文、丢弃更早轮次",并 `log`,绝不因摘要失败而整轮失败。

## 5. 测试(完工必须全绿)
- `contextWindow` 纯函数单测:短历史不压缩、超长触发压缩、system 永留、保守余量、未登记模型走默认。
- 能力表单测:命中/未命中默认。
- 对话链路回归:现有 `agentConversationReliability.test.mjs`、`providerGateway.test.mjs`、`AgentCenterModule.test.mjs` 不回归。
- 流式可切换 + 非流式调用方零回归。
