# 出海翻译完整模块集成设计

## 1. 目标

把 `/Users/feiyanglin/Downloads/出海翻译-完整模块集成包-2026-07-17` 中已经形成行为契约的出海翻译能力，安全地合入梅奥当前版本 `feat/stability-phase2`，完成本地、真实浏览器、真实供应商任务、GitHub 和腾讯云生产发布闭环。

本次交付不是文件快照覆盖。集成包来自另一个工作区快照，而当前版本已经包含更晚的项目卡恢复、账号隔离、provider、任务状态和部署安全修复。所有能力必须按行为迁移并适配当前主线。

## 2. 已确认的产品范围

保留并回归现有能力：

- 主图出海、详情出海、去文案。
- `AI直出`、`AI优化`，并兼容历史值 `策划分析` 归一为 `AI优化`。
- 原图、固定比例、自定义尺寸及现有模型能力约束。
- 已有项目卡、任务同步、托管素材和下载入口。

新增完整模块能力：

- `产品隔离` 与 `全局翻译` 两种翻译范围。
- 首次提交前冻结不可变的 `TranslationConfigSnapshot`。
- 对主图和详情图结果执行重试，保留根结果、直接来源、次数、素材顺序和费用谱系。
- 对已成功的主图和详情图执行单张区域修改；一次允许 1 至 5 个矩形区域。
- 区域修改支持纯删除、文字替换和混合局部修改。
- 模型输出只合成到选区内，框外像素使用当前源版本保护。
- 修改版本保持首次选择的目标画布尺寸。
- 修改任务支持生成中、成功、失败、取消、刷新恢复和版本切换。
- 单张和批量下载选择有效的成功版本，并将临时上游资源镜像为受管资源。

不在本次范围内：

- 不改账户、积分或支付规则。
- 不引入数据库迁移；新字段继续存放在既有 JSON metadata、项目结果和版本记录中。
- 不重构其他图片模块，不把 Translation 区域编辑工具推广为全局公共编辑器。
- 不覆盖当前主线的完整 `ShellMigratedApp.tsx`、`server/index.mjs`、package 文件或配置文件。
- 不更新 GitHub 默认分支 `main`；提交和推送当前实际发布分支 `feat/stability-phase2`。

## 3. 集成策略

采用行为级迁移：

1. 先迁入 Translation 命名空间内的纯领域模块与测试。
2. 再补齐当前主线的类型契约。
3. 逐点接入输入栏、Shell 编排、项目卡、适配器、持久化、服务和 provider。
4. 每一个可测试行为先增加失败测试，再写最小实现。
5. 当前主线与集成包发生冲突时，保留当前主线的安全、账号隔离、任务状态、素材托管和恢复合同，只迁入缺失的 Translation 行为。

集成包的 `FILE_INVENTORY.sha256` 使用 CRLF 行尾。直接执行 macOS `shasum -c` 会把 `\r` 当作文件名字符而误报全部缺失；只读去除 `\r` 后，102 个清单文件均通过哈希校验。实施时不得为此修改或重打包原集成包。

## 4. 组件边界

### 4.1 Translation 领域层

`src/modules/Translation/` 负责：

- 配置快照归一化与合法性验证。
- 重试身份、谱系、排序、费用和下载路径。
- 区域坐标、输入验证、意图分类、提示词和请求图片顺序。
- 引导图生成、受保护局部合成和目标画布约束。
- 编辑版本状态机、恢复候选、合并、账号 scope 和持久化事务辅助。
- 结果资源选择、镜像替换和下载候选。

这些模块不得直接依赖 React 全局状态或账户 UI。涉及 DOM/canvas 的代码通过显式 loader、signal 和回调注入，便于测试取消、跨账号和资源失败。

### 4.2 Shell 宿主层

`src/ShellMigratedApp.tsx` 只负责业务编排：

- 在首次生成前冻结配置。
- 调用 AI优化分析和图片生成。
- 创建重试结果和编辑版本占位。
- 将 provider task id、费用和终态按稳定身份写回。
- 在刷新后恢复尚未完成受保护合成的编辑版本。
- 把下载、重试、编辑和取消动作传给 Translation UI。

`BottomInputBar.tsx` 负责收集并展示 Translation 参数；`ProjectListView`、`ProjectCard` 和 Shell Translation 模块只负责展示与动作透传，不复制领域判断。

### 4.3 适配与持久化层

`shellDataAdapter.ts` 和 `shellPersistence.ts` 必须支持：

- 普通翻译、重试和区域编辑三类任务身份。
- 项目结果按 result id 合并，编辑版本按 version id 合并。
- 稀疏后台记录只能补字段，不能清空更完整的图片、区域、尺寸、错误、费用或谱系。
- 终态错误不得被旧的 generating 记录复活。
- 已完成的受保护版本不得被原始 provider 输出覆盖。
- 账号切换、删除 tombstone 和 shell scope 继续沿用当前主线规则。

### 4.4 服务与 provider 层

复用当前内部任务 API、托管资源和 KIE 图片 provider。服务端只迁移当前主线缺失的 Translation metadata、单次任务探测或图片后处理合同，不复制集成包中的宿主文件。

所有 provider 调用必须：

- 保持现有鉴权和密钥边界。
- 保留 `providerTaskId`，已提交任务只恢复或查询，不重复创建付费任务。
- 纯删除只传区域引导图；替换或混合任务先传当前源图，再传区域引导图。
- provider 成功且存在有效图片时，不使用“视觉差异太小”作为失败依据。

## 5. 数据契约

### 5.1 配置快照

`TranslationConfigSnapshot` 至少包含：

- subfeature、生成模式、翻译范围、目标语言。
- 比例、目标宽高、图片数量、质量和模型选择。
- 用户提示/补充要求和来源素材身份。
- 首次提交时的原图宽高及最终目标画布。

快照首次提交后不可变；重试和刷新恢复不得重新读取当前输入栏参数。

### 5.2 重试结果

重试结果至少包含：

- `retryOfResultId`：本次直接来源。
- `retryRootResultId`：首次结果。
- `retryAttempt`、`sourceOrder`、配置快照、provider/job 身份和实际费用。

重试创建新结果，不覆盖原失败或成功记录。

### 5.3 编辑区域与版本

区域使用图片内容坐标或 0..1 归一化坐标，不持久化 DOM 坐标。每个区域有稳定 id、矩形和非空指令，允许触碰四边，最多 5 个，不允许非法数字、过小矩形或相互重叠。

编辑版本至少包含：

- version id、状态、创建/更新时间。
- source version id、source url、原始 provider 输出和最终受保护图片。
- regions、目标宽高、backend job id、provider task id、费用和错误。

失败版本不展示图片、不成为下载候选，也不得替换当前成功版本。

## 6. 数据流

### 6.1 首次生成

输入栏参数归一化 → 冻结配置快照 → 创建项目与结果占位 → AI优化时执行规划 → 生成 RTCFE 图片提示词 → 提交内部图片任务 → 写入 task id 与费用 → 成功后镜像资源、更新结果并持久化。

原图模式必须取得真实源图尺寸；拿不到时终止提交并显示：`原图尺寸读取失败，请重新上传素材后再生成。`

### 6.2 重试

选择可重试结果 → 从结果/项目/历史结构化提示中解析有效快照 → 创建新重试结果 → AI优化重新规划、AI直出跳过规划 → 提交新图片任务 → 按同一重试结果 id 写入终态 → 排在对应根结果之后。

### 6.3 区域修改

选择当前成功版本 → 框选并校验区域 → 创建 generating 编辑版本并立即收起编辑器 → 生成引导图和 RTCFE 提示词 → 提交图片任务 → 记录原始输出 → 以当前源图为底执行局部合成 → 调整到首次画布 → 上传受管资源 → 项目和文件两层持久化都成功后提交 completed 版本。

中间任意步骤失败，只把本次编辑版本置为 error，保留此前成功图片。

### 6.4 刷新恢复

水合任务和项目 → 识别已拿到原始输出但尚未完成局部保护的版本 → 校验项目、结果、版本、账号和 task identity → 最多一个恢复任务在途 → 局部合成、上传和持久化 → 若期间账号或版本状态变化则丢弃旧异步结果。

### 6.5 下载

单张下载优先当前选择的成功编辑版本，再取最新成功编辑版本，最后回退首次成功结果。批量下载对每个结果执行同一选择规则。失败或生成中的版本不可下载；临时外链先镜像为受管资源。

## 7. 错误处理和防回归原则

- 配置、翻译范围、区域、尺寸或来源身份不合法时 fail-closed，不静默回落到其他业务语义。
- 任何等待 provider 的链路一拿到 task id 就持久化 checkpoint。
- 旧账号、旧版本或旧任务的异步完成不得写回当前账号。
- 取消必须按精确 owner/version 身份执行；晚到 task id 仍要保持该版本终态。
- 项目持久化和文件持久化组成一个逻辑提交；任一失败都不切换可见成功版本。
- region guide 只用于模型定位，不成为永久源图或最终输出。
- 提示词遵守 RTCFE，用户区域指令序列化为数据，避免换行、标签字符和指令注入破坏模板。
- 其他模块的项目卡、任务恢复、下载和 provider 行为必须保持不变。

1. 主图出海首次生成：AI直出 + 产品隔离。

3. 对可重试主图或详情结果执行一次重试。
4. 对成功结果执行一次纯删除区域修改。
5. 对成功结果执行一次文字替换或混合区域修改。

随后验证刷新恢复、单张下载、批量下载、图片尺寸、托管 URL、task id、实际费用和日志。不得通过破坏生产 provider 配置来人为制造失败；错误路径由自动化测试和已有失败样本回放覆盖。

## 9. 代码审查、发布和回滚

完成实现后对完整 diff 做独立代码审查，Critical 和 Important 问题必须清零。审查重点：账户隔离、重复付费任务、持久化覆盖、旧状态复活、临时 URL、提示词契约、其他模块回归和部署所有权。

发布顺序：

1. 提交经过验证的实现到 `feat/stability-phase2`。
2. 推送 `origin/feat/stability-phase2`。
3. 等待真实运行任务和长连接自然排空，不设置 `MEIAO_DEPLOY_ALLOW_ACTIVE_JOBS=1`。
4. 通过 `MEIAO_CODE_REVIEW_CONFIRMED=1 ./scripts/deploy_tencent.sh` 发布。
5. 验证服务器本机和两个备案域名 `/api/health`、Temporal worker、PM2、marker/mutex、关键源码哈希和生产前端资源链。
6. 在线上测试账号回放至少一条生成/恢复链路，确认刷新和下载。

若云上验证失败，停止继续真实任务。部署脚本构建或切换失败时沿用脚本保留的旧 `dist`；若新代码已经启动但核心合同失败，回滚到本次集成前已验证提交并重新走同一门禁发布。不得直接删除 marker/mutex 或在未知所有权下手工覆盖云上目录。

## 10. 完成标准

只有以下条件全部成立才算完成：

- 包内目标能力已按当前主线合同接入，旧 Translation 项目仍可读取。
- 定向测试、全量 verify、lint、build、doctor 和 diff 检查通过。
- 真实浏览器宽屏/窄屏、刷新和下载验收通过。
- 五条真实任务覆盖首次生成、重试、纯删除和文字替换，结果与任务证据可追溯。
- 独立代码审查无 Critical/Important 遗留。
- GitHub 发布分支包含提交，腾讯云源码与本地关键文件一致。
- 双域名 health 和 worker 健康，PM2 online，无残留部署 marker/mutex。
- 最终交付列出 commit、测试结果、真实任务 id、部署状态、云上哈希和已知残余风险。
