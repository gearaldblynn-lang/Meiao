# 短视频音视频裁剪与转码设计

## 背景

短视频生成当前对参考视频和参考音频使用宽泛的 `video/*`、`audio/*` 文件选择范围。文件选中后会立即进入材料池并开始后台上传，直到 Seedance Fast 接收素材时才可能因容器、编码、时长、分辨率、帧率或大小不符合要求而失败。

仓库已经能够识别 MP4 中的 HEVC/H.265，并在预览黑屏时提示转换为 H.264，但没有真正的转码能力。用户已确认：所有视频和音频上传都建议经过统一裁剪与标准化；界面采用单屏弹窗，允许拖动范围条选择片段；转换完成后再写入托管素材；页面风格复用梅奥工作台现有设计语言。

## Seedance Fast 输入合同

### 参考视频

- 输出容器：MP4（上游也接受 MOV，但站内统一为 MP4）。
- 单文件时长：2–15 秒。
- 最多 3 个文件，同一任务全部参考视频总时长不超过 15 秒。
- 输出分辨率：720p；宽高比在 0.4–2.5；宽高在 300–6000 像素；总像素在 409600–927408。
- 帧率：24–60 FPS，站内统一为 30 FPS。
- 单文件不超过 50 MB。

### 参考音频

- 输出格式：MP3（上游也接受 WAV，但站内统一为 MP3）。
- 单文件时长：2–15 秒。
- 最多 3 个文件，同一任务全部参考音频总时长不超过 15 秒。
- 单文件不超过 15 MB。

### 上传入口提示

短视频模块的参考视频和参考音频上传入口增加信息图标与鼠标悬浮提示，完整展示格式、数量、单文件/总时长、尺寸、像素、帧率和大小限制。提示只负责提前说明，文件选中后仍由服务端真实探测和校验。

文件选择器继续接受宽泛的音视频格式，因为不兼容源文件正是转码功能需要处理的输入，不能用 `accept` 在选择阶段将其隐藏。

## 方案比较

### 方案 A：浏览器内 FFmpeg/WASM

优点是源文件不需要先传到服务端。缺点是首次加载体积大、浏览器内存峰值高、弱机器容易崩溃，HEVC 和冷门容器的实际解码能力还会因构建产物而变化。它不适合作为内部多人生产工具的统一能力。

### 方案 B：服务端临时会话 + FFmpeg 转码（采用）

源文件只写入受控临时目录，服务端用 FFprobe 读取真实元数据。用户确认裁剪范围后，FFmpeg 生成规范文件，再调用现有托管素材存储写入正式素材。实现边界清晰、编解码能力稳定，也不会把大文件塞进数据库或前端状态。

### 方案 C：接入现有持久任务/Temporal 队列

它能提供跨刷新恢复和精确后台进度，但需要让临时文件、任务恢复、清理、状态水合和现有付费任务系统耦合。转码属于提交前可安全重试的本地准备步骤，第一版不应扩大付费任务状态面。

## 用户交互

### 选择文件

1. 用户在短视频“参考视频”或“参考音频”入口选择一个或多个文件。
2. 系统不立即加入材料池，也不上传到正式图床，而是按选择顺序逐个打开裁剪弹窗。
3. 弹窗打开后立即显示本地可用的预览；同时把当前文件上传到服务端临时会话并显示“正在分析素材”。浏览器不能解码的格式使用通用占位，但不影响服务端探测。
4. 服务端返回格式、编解码器、时长、宽高、帧率和大小后，弹窗启用裁剪范围。

### 单屏裁剪弹窗

- 沿用工作台 `--bg-*`、`--text-*`、`--accent`、`--border-*` 和 `--shadow-elevated` 变量；使用当前弹窗的 28px 外圆角、模糊遮罩、蓝色主操作和次级取消按钮。
- 视频预览使用 `object-contain`：横屏宽度优先、竖屏高度封顶、方形和特殊比例完整显示，不为填满弹窗裁掉源内容。
- 音频使用同位置波形/轨道占位，裁剪控制不跳位。
- 双手柄范围条选择开始和结束位置，选中区间必须在 2–15 秒内。
- 弹窗显示源文件检测结果和固定推荐输出：视频为 `MP4 · H.264 · AAC · 720p · 30 FPS`，音频为 `MP3`。
- 主按钮为“转换并继续”。转换期间锁定手柄和关闭操作，显示“转换中 → 保存素材中 → 已就绪”；用户主动取消时中止请求并清理临时文件。

### 多文件和总时长

- 同一类素材最多保留 3 个，文件按选择顺序逐个处理，避免并发转码打满 CPU。
- 每次裁剪时显示同类已占用时长和本文件剩余可选预算。
- 单文件不足 2 秒直接拒绝。
- 单文件或同类总时长超过 15 秒时，不自动截断；范围条限制可选区间，用户必须主动选择符合限制的片段。
- 材料加入前和创建 Seedance 任务前各校验一次数量与总时长，防止历史状态或绕过 UI 的请求进入 provider。

## 服务端架构

### 媒体转码模块

新增独立 `server/mediaTranscode.mjs`，负责：

- FFmpeg/FFprobe 可用性检查；
- 元数据解析与 Seedance 合同校验；
- 视频目标尺寸计算和 FFmpeg 参数生成；
- 音频 MP3 参数生成；
- 子进程超时、取消和错误归类；
- 临时会话创建、读取、所有权校验和清理；
- 进程级转码并发闸门与运行状态摘要。

FFmpeg 二进制解析顺序为显式环境变量、项目内静态依赖、系统 PATH。生产可以通过环境变量固定经过验证的二进制路径，避免升级时静默换版本。

### 两阶段 API

1. `POST /api/media-transcodes/sessions`
   - 登录用户上传一个源文件和 `kind=video|audio`。
   - 路由先按 `Content-Length` 执行独立输入上限，再解析 multipart。
   - 文件写入服务端临时目录，FFprobe 返回 `sessionId` 和非敏感元数据。
   - 原始文件不进入 `stored_assets`、COS、KIE 或任务表。

2. `POST /api/media-transcodes/sessions/:id/convert`
   - 请求体包含 `startSeconds`、`endSeconds` 和模块名。
   - 服务端校验会话属于当前用户、范围为 2–15 秒且不越界。
   - 转码完成后再次 FFprobe；只有满足输出合同才写入正式托管素材。
   - 返回 `fileUrl`、`assetId`（如有）、标准文件名、MIME、时长、宽高、帧率和大小。
   - 成功或失败都清理临时源文件和输出文件。

3. `DELETE /api/media-transcodes/sessions/:id`
   - 仅会话所有者可取消。
   - 中止正在运行的 FFmpeg，并删除临时目录。

MySQL 与本地 JSON 模式共用同一业务处理函数，只在身份校验与日志写入处注入不同适配器，避免再复制两套转码逻辑。

### 视频标准化

- 输出：MP4、H.264、AAC、`yuv420p`、`+faststart`、30 FPS。
- 在源宽高比 0.4–2.5 内完整保留比例；以 720px 短边为优先并限制长边不超过 1280px，结果尺寸取偶数，确保总像素在上游范围内。
- 超出 0.4–2.5 的极端比例不拉伸、不裁主体；缩放后放入最近允许比例的画布并居中补边。
- 使用受控质量/码率，使 15 秒输出稳定低于 50 MB；转码后仍以真实文件大小做硬校验。
- 没有音轨的视频保持无音轨；有音轨时转为 AAC。

### 音频标准化

- 输出 MP3，固定采样率与受控码率。
- 裁剪后真实时长必须在 2–15 秒，大小必须低于 15 MB。

### 容量、超时与清理

以下参数全部由环境变量控制并提供保守默认，不在业务代码散落硬编码：

- 单个源文件最大字节数；
- 转码并发数（默认 1）；
- 单次 FFprobe/FFmpeg 超时；
- 临时会话 TTL；
- 临时目录总容量或最大会话数；
- 视频/音频输出大小上限。

服务启动时清理过期会话，运行中定期回收；用户取消、转换成功、转换失败和进程超时都立即清理。临时路径、密钥、签名 URL 和媒体内容不得进入业务日志。

## 前端边界

新增独立组件和纯状态逻辑：

- `MediaTrimTranscodeDialog`：预览、分析态、范围选择、转换状态和错误反馈。
- `mediaTranscodeClient`：创建会话、转换、取消。
- `mediaTrimRules`：2–15 秒范围、同类最多 3 个、同类总时长 15 秒的纯函数。

当前生产路由中的 `BottomInputBar` 同时承载短视频生成、参考音频和分镜爆款参考视频上传，统一进入同一处理器。成功后才创建 `Material`，保存服务端返回的 `remoteUrl`、标准文件名、MIME、时长和转码标记；原始不兼容 `File` 不再进入现有 `uploadInternalAssetStream`。未被 `ShellMigratedApp` 路由使用的旧版 `src/modules/Video` 侧栏不在生产链路内，本次不为它复制第二套实现。

图片上传链路保持不变。

## 错误处理和计费安全

- 分析、裁剪、转码和托管属于任务创建前的准备阶段；失败时不创建 Seedance job、不预留积分、不写项目失败卡。
- 用户取消只记录素材处理取消，不触发 provider 调用。
- FFmpeg 不可用、输入损坏、时长不足、范围无效、输出不合规、超时、容量不足和托管失败使用不同错误码，并给用户可执行中文提示。
- 转码成功但正式素材保存失败时不把临时路径返回前端；清理输出并允许用户重试。
- 最终 provider 边界继续验证数量、时长和 URL，不能把前端校验当安全边界。

## 日志和健康状态

业务日志增加 `media_transcode_started/completed/failed/cancelled`，仅记录：模块、媒体类型、源/目标容器和编解码器、源/目标时长、宽高、帧率、大小、耗时与结构化错误码。

`/api/health` 增加非敏感的转码摘要：FFmpeg/FFprobe 是否就绪、活动数、排队数和临时会话数。不得返回二进制绝对路径或用户文件名。

## 测试与验收

### 自动化

- 纯函数：视频尺寸、极端比例补边、裁剪范围、总时长和数量限制。
- 服务端：FFprobe 解析、FFmpeg 参数、超时/取消、会话所有权、TTL 清理和输出合同。
- API：MySQL/本地两种路由均要求登录并校验同一用户；源文件在转换成功前不进入正式素材。
- 前端：视频/音频队列、分析失败、范围手柄、取消、多文件总时长、成功后才加入材料池。
- 现有 HEVC 识别、素材上传、Seedance provider 和分镜生命周期测试保持通过。

### 本地真实探针

使用 FFmpeg 生成短小的测试素材，至少覆盖：

- HEVC/H.265 视频输入转为 H.264/MP4；若当前 FFmpeg 构建缺少 HEVC 编码器，只影响测试素材的现场生成，仓库使用已固化的小型 HEVC fixture 完成同一解码回归；
- 横屏、竖屏和极端比例；
- WAV 转 MP3；
- 指定 2–15 秒裁剪；
- 转码输出经 FFprobe 满足时长、格式、编码、尺寸、像素、帧率和大小合同；
- 取消后无临时文件残留。

不创建真实 Seedance 付费任务。最终运行相关测试、`npm run lint`、`npm test` 和 `npm run build`。

## 发布与回滚

发布前检查云机 FFmpeg/FFprobe 可用性、临时目录容量和转码并发配置。灰度时只用本地准备与托管素材验证，不提交付费视频任务；确认日志、health、临时清理和输出合同后再开放入口。

转码入口由环境开关控制。回滚时关闭入口，前端恢复原有上传提示；现有已转换素材仍是普通托管 MP4/MP3，可继续使用，不需要数据迁移。

## 本次不做

- 不做完整视频剪辑器、拼接、字幕、滤镜或音量编辑。
- 不自动截取开头 15 秒；所有内容裁剪由用户主动选择。
- 不把临时转码会话写入项目状态或付费任务表。
- 不改变 Seedance 模型、积分、付费提交和恢复策略。
