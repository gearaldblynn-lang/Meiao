## 3. 架构设计

### 3.1 工具集（V2 动态注入）

```
runAgentConversationV2 构造 tools 时,按智能体能力动态注入：
- imageGenerationEnabled        → generate_image (function, 出图走 KIE)
- 绑了知识库(knowledgeBaseIds)  → search_knowledge (function, 走第3期向量检索)
- webSearchEnabled              → web_search (responses 内置工具, {type:'web_search'})
都不满足 → 无 tools, 纯对话
```

### 3.2 端点迁移：chat/completions → responses

新增 `server/openaiResponsesProvider.mjs`（与第2期 `openaiToolCalling.mjs` 并存，逐步替代）：
- 请求：`POST /v1/responses`，body `{model, input:[{role,content}], tools, ...}`
- 解析 `output[]`：
  - `type:'message'` → 取 `content[].text`（output_text）作为助手回复
  - `type:'function_call'` → 自定义工具调用（generate_image / search_knowledge）
  - `type:'web_search_call'` 等内置工具 → 模型已自主联网，结果已并入 message
- 多轮工具结果回传：function 结果作为 `{type:'function_call_output', call_id, output}` 加进 input 续传
- 流式：responses 端点 SSE（若支持），不支持则非流式 + 整段回传（第1期 SSE 降级逻辑兼容）

### 3.3 模块划分

| 文件 | 职责 | 新建/改 |

## 4. 工具定义

### 4.1 search_knowledge（知识库检索）

```json
{
  "type": "function",
  "name": "search_knowledge",
  "description": "检索智能体绑定的私有知识库。当用户问题涉及产品规则、政策、流程、FAQ 等专有知识时调用。",
  "parameters": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "检索关键词或问题,用自然语言描述要查什么" }
    },
    "required": ["query"]
  }
}
```
- 执行：后端收到 → 调第3期 `searchKnowledgeChunksByVector(query, 该智能体的chunks, policy, env, 关键词fallback)` → 把命中知识块作为 function_call_output 回传模型
- **仅当智能体绑了知识库才注入此 tool**（无知识库注入了也没数据）

### 4.2 web_search（联网，号池内置）

```json
{ "type": "web_search" }
```
- responses 端点内置工具，模型自主决定何时联网，搜索结果自动并入回复
- **仅当智能体 webSearchEnabled 才注入**
- 后端不需要执行逻辑（号池侧执行），只需透传工具声明 + 解析最终回复

### 4.3 generate_image（生图，沿用第2期）

- `imageToolDefinition.mjs` 的 `GENERATE_IMAGE_TOOL` 转成 responses 端点的扁平 function 格式（`{type:'function', name, description, parameters}`，不是 chat 的嵌套 `{type:'function', function:{...}}`）
- 执行不变：走 KIE 出图

## 5. V2 编排改造

`runAgentConversationV2` 升级：

```
1. 构造 tools（动态）:
   tools = []
   if imageGenerationEnabled: tools.push(GENERATE_IMAGE_TOOL_RESPONSES)
   if hasKnowledgeBase:       tools.push(SEARCH_KNOWLEDGE_TOOL)
   if webSearchEnabled:       tools.push({type:'web_search'})
2. callModel(responses 端点) → 解析 output
3. 工具循环（最多 N 轮,防失控）:
   - function_call: generate_image → 出图(KIE) → function_call_output 回传
   - function_call: search_knowledge → 向量检索 → 命中知识块作 output 回传
   - web_search_call: 号池已执行,结果在 message 里,无需后端处理
   - 无 function_call(只有 message) → 结束,返回最终回复
4. 进度 SSE: thinking / tool_calling(标明哪个工具) / searching_knowledge / image_generating / web_searching / done
```

**工具循环上限**：知识库检索允许多轮（模型可能查几次），生图仍限一次。总轮数上限（如 5 轮）防失控。

## 6. 降级与兼容

| 场景 | 行为 |
|------|------|
| responses 端点不可用 | 抛错，前端提示对话服务暂不可用（不静默回退 chat 端点——格式不同） |
| search_knowledge 检索失败 | function_call_output 回传"检索失败"，模型据此回复，不中断 |
| 智能体没绑知识库 | 不注入 search_knowledge tool |
| 智能体未启用 webSearch | 不注入 web_search tool |
| 未配 toolCallingProvider 的智能体 | 仍走旧路径（`runAgenticRetrievalLoop`），不受影响 |
| 生图 | 仍走 KIE，迁端点后出图行为不变 |

## 10. 验收（业主视角）

- 配一个智能体：toolCallingProvider + 绑知识库 + 启用 webSearch + 启用生图
- 问知识库内问题 → 模型调 search_knowledge,召回正确知识块作答
- 问实时信息（今天新闻/股价）→ 模型联网,给真实最新数据
- 要求画图 → 模型调 generate_image,KIE 出图（行为不变）
- 一轮对话里混合需求（先查知识库再生图）→ 多工具按需触发
- 没绑知识库的智能体 → 不会乱调 search_knowledge
- MySQL 模式和本地 JSON 模式一致
