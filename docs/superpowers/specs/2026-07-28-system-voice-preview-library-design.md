# 系统预置口播音色试听库设计

**日期：** 2026-07-28  
**状态：** 用户已授权直接实施  
**适用范围：** 本地当前版本、GitHub 发布分支、腾讯云生产环境

## 1. 目标

把当前“用户点击音色后，按账号临时调用 KIE 生成试听”的流程改为“系统一次生成、版本内永久携带、所有账号直接播放”。

系统必须为当前 Gemini 3.1 Flash TTS 目录中的 30 个音色预先生成中文试听音频。资源随代码构建和腾讯云同步发布；用户点击播放按钮时优先直接播放静态音频，不再等待生成，也不产生重复的 KIE 费用。

## 2. 现状与根因

当前试听注册表和音频都位于 `server/data`：

- `server/data/voiceover-preview-cache` 保存按账号隔离的试听状态。
- `server/data/assets` 保存生成后的托管音频。
- `.gitignore` 排除 `server/data/`。
- `scripts/deploy_tencent.sh` 明确排除并保留云端 `server/data`。

因此，本地已生成试听既不能进入 Git，也不会随腾讯云发布同步。继续扩大账号缓存只会让每个账号重复生成，不能实现“本地生成一次，云上同步后已有数据”。

## 3. 产品合同

- 预置库覆盖 `VOICEOVER_VOICES` 中的全部 30 个音色，不能少、不能重复、不能包含目录外音色。
- 每个音色使用同一条简短中文试听文案，确保用户比较的是音色而不是文案差异。
- 音频是系统共享产品资源，不属于某个用户，不写入账号素材库或账号运行数据。
- 前端拿到有效的 `previewUrl` 后直接播放静态音频，不调用 `/api/voiceover/voice-previews`。
- 只有预置资源缺失或校验失败时，才保留现有按账号生成接口作为兼容兜底。
- “自动匹配”不是一个固定 Gemini 音色，不生成独立试听。
- 本次不改变正式口播翻译任务的 TTS 音色选择、计费、时间轴对齐和最终视频混音。

## 4. 资源结构

可部署资源存放在：

```text
public/voiceover-previews/
  manifest.json
  Zephyr.wav
  Puck.wav
  ...
  Sulafat.wav
```

`manifest.json` 是运行时和验证工具共同读取的权威索引：

```json
{
  "version": 1,
  "model": "google/gemini-3-1-flash-tts",
  "language": "cmn",
  "sampleText": "你好，这是一段口播音色试听。",
  "voices": [
    {
      "name": "Zephyr",
      "file": "Zephyr.wav",
      "contentType": "audio/wav",
      "bytes": 12345,
      "sha256": "..."
    }
  ]
}
```

部署清单不得包含 API key、账号身份、认证信息或 provider task id。provider task id 只进入被 Git 忽略的本地生成台账，用于中断恢复和防止重复付费提交。

## 5. 生成与恢复

新增一次性生成命令，行为必须幂等：

1. 读取系统音色目录、现有清单、音频文件和本地生成台账。
2. 对已存在资源校验音色名、字节数、SHA-256 和可识别音频类型；有效则跳过。
3. 对台账中已存在 `providerTaskId` 的未完成音色只查询原任务，不创建第二个任务。
4. 只有显式设置一次性付费确认开关时，才允许为没有 provider task id 的音色创建新 KIE 任务。
5. 默认串行生成，避免瞬间创建 30 个付费任务；并发、请求超时和轮询限制通过环境变量设置并使用保守默认值。
6. 下载成功后先校验响应类型和非空字节，再原子写入音频；每完成一个音色就原子更新台账和部署清单。
7. 任一提交结果未知时停止该音色的自动重提，保留 task id 或未知状态并返回非零，避免重复扣费。
8. 只有全部 30 个音色均通过完整性校验，命令才以成功退出。

生成器复用现有 KIE TTS 创建、查询和结果归一化能力，但使用专门的系统预置任务身份，不伪装成用户口播翻译子任务。

## 6. 运行时接入

服务启动时读取并校验系统试听清单：

- 清单版本、模型、语言和音色名必须符合当前代码目录。
- `file` 必须是安全的单层文件名，不能路径穿越。
- 文件必须存在，字节数和 SHA-256 必须匹配。
- 只有通过校验的条目才映射为 `/voiceover-previews/<file>`。

`getVoiceoverPublicConfig()` 给每个音色增加可选 `previewUrl`：

```ts
{
  name: "Zephyr",
  trait: "Bright",
  tags: [1, 3],
  previewUrl: "/voiceover-previews/Zephyr.wav"
}
```

无效或缺失资源只导致该音色没有 `previewUrl`，不能让整个服务启动失败；后台记录脱敏告警，前端对该项走现有生成兜底。

## 7. 前端交互

音色弹层保持现有布局和播放按钮：

- 点击有 `previewUrl` 的音色：立即创建/复用 `Audio` 播放静态 URL。
- 再次点击同一音色：停止或重新播放，不发生成请求。
- 切换音色：停止上一段，再播放新音色。
- 播放中、暂停和失败状态继续用现有图标/提示。
- 静态音频加载失败时，自动清除该 URL 的内存可用状态并调用现有账号试听 API 一次作为兜底。
- 组件卸载或弹层关闭时停止播放并释放事件监听。

## 8. 发布与安全

- `public/voiceover-previews` 随 Vite 构建复制到 `dist/voiceover-previews`，也随发布脚本同步到腾讯云。
- 不修改 `server/data` 的发布排除规则，不覆盖任何云端用户数据。
- Git 只跟踪部署清单和经过校验的音频，不跟踪生成台账、provider task id 或密钥。
- 资源 URL 是公开的产品试听素材；不使用账号认证 URL，也不携带签名参数。
- 云上发布后逐个验证 30 个 URL 返回 200、音频内容类型、字节数和 SHA-256 与清单一致。

## 9. 验收

自动化验收必须覆盖：

- 清单与当前 30 个音色一一对应。
- 所有音频存在且字节数、SHA-256 和类型匹配。
- 生成器跳过有效资源、恢复已有 task id、未知提交不自动重提、无确认开关不创建付费任务。
- 公共配置只暴露通过校验的 `previewUrl`，且不泄露本地路径或生成台账。
- 前端优先直接播放预置 URL，静态加载失败才调用账号试听 API。
- `npm run build` 后 `dist/voiceover-previews` 完整存在。

真实验收必须覆盖：

- 本地浏览器连续试听多个音色，点击后直接播放，不出现“正在生成真实音色试听”。
- 本地网络面板不出现音色试听 POST；静态资源请求为 200。
- 腾讯云发布后重复同样验收，确认多账号共享同一资源且不产生新的 KIE 试听任务。
